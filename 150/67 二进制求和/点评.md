# 67. 二进制求和 — 代码点评

## 使用的方法
**竖式模拟 + 字符串前插**：`flag` 当进位，先双指针同时从 `a`、`b` 末尾逐位相加，再用两段 `while` 分别处理较长串剩余的高位，最后若仍有进位就在最前面补 `'1'`。每一位的结果先用临时串 `t = sum % 2 + '0'` 拼好，再 `res = t + res` 插到结果最前面。

## 复杂度分析
- 时间复杂度: O(L²)（L = max(|a|, |b|)；每处理一位都要把已有结果整体拷贝一次，累计约 L²/2 次字符搬运）
- 空间复杂度: O(L)（结果串 + 每步的临时串）

## 代码评价
- 优点:
  - 加法逻辑完全正确：进位 `flag = sum / 2`、当前位 `sum % 2`，先处理公共低位、再处理剩余高位、最后补最高进位，三段覆盖了所有长度组合
  - 边界安全：`a` 或 `b` 为空串时 `length() - 1` 得 -1，循环自然跳过，不会越界
  - 用 `flag` 承接进位、不回头改已写入的字符，思路清晰
- 可改进之处:
  - **`res = t + res` 是前插**，每步都要把已有结果整体右移拷贝，整体退化成 O(L²)。本题 L ≤ 10⁴ 仍能过线，但改成 `res.push_back(...)` 收集、最后 `reverse` 一次就是干净的一趟 O(L)
  - 三段 `while` 可以合并成一段 `while (n1 >= 0 || n2 >= 0 || flag)`，缺失位用 `n1 >= 0 ? a[n1] - '0' : 0` 补，代码能缩短一半
  - 每字符 `string t = ""; t += ...; res = t + res;` 会构造两个临时串；注意 `res.insert(res.begin(), ch)` 同样是 O(L) 搬移，别用它替代前插
  - 参数是值传递，可以像题解解法二那样**在较长的串上原地累加**（`swap` 后逐位回写），额外空间降到 O(1)
- 代码风格: `n1 / n2 / flag` 命名偏随意，进位建议改名 `carry`；三处重复的 `sum` 计算块可合并

## 总结
> 竖式加法的进位与长度处理都正确，AC；主要问题是"前插拼结果"带来的 O(L²) 搬运和每字符的临时串开销，换成 push_back + reverse（或直接在长串上原地算）就是最优写法。
> AC ✓
