# 71. 简化路径 — 代码点评

## 使用的方法
**手动分割 + 栈模拟**。逐字符遍历路径，遇到 `/` 时处理已积累的目录名；使用 `stack<string>` 处理 `..` 回退和普通目录入栈；最后从栈顶逆序拼接结果。

## 复杂度分析
- 时间复杂度: O(n + k²L)，n 为路径长度，k 为栈中目录数，L 为平均目录名长度。其中 n 来自单次遍历，k²L 来自逆序字符串拼接（每次 `p = w + p` 需要拷贝整个已有字符串）
- 空间复杂度: O(n)，栈存储所有有效目录名

## 代码评价
- 优点:
  1. 手动逐字符解析，逻辑清晰，无额外库依赖
  2. 对 `.`（当前目录）、`..`（上级目录）、空目录名三种情况处理正确
  3. 正确处理了路径不以 `/` 结尾的情况（末尾 word 在循环外单独处理）
  4. 根路径 `/` 的特殊情况也正确处理（空结果补 `/`）
- 可改进之处:
  1. **代码重复**: 循环内（18-26 行）和循环外（34-42 行）的 word 处理逻辑完全重复。可在循环末尾统一处理，或把循环条件改为 `i <= path.length()` 以统一处理末尾
  2. **字符串拼接效率**: 用 `p = w + p` 逆序拼接导致 O(k²) 字符拷贝。建议改用 `vector<string>` 存储（保持插入顺序），最后正向拼接为 O(n)
  3. **空语句风格**: `if (word == "." || word == "") ;` 的分号独占一行不够显眼，建议用 `continue` 或加注释
  4. **`stack` 可用 `vector` 替代**: 使用 `vector` + `push_back/pop_back` 既保持插入顺序（省去逆序拼接的逆序步骤），也支持栈操作
  5. **未使用的 header**: `<map>` `<set>` `<algorithm>` 可删除
- 代码风格: 整体结构清晰，缩进一致；main 函数的测试用例设计合理

## 总结
> 手动分割 + 栈的经典解法，逻辑正确，但末尾处理代码重复且逆序字符串拼接效率偏低；改用 vector 可一并解决。
