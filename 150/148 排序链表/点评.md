# 148. 排序链表 — 代码点评

## 使用的方法
自顶向下归并排序：先处理长度 1/2 的基准情况，再用快慢指针（`l` 步进 1、`r` 步进 2）找中点，切断成两半后分别递归排序，最后手写 `merge` 合并两个有序链表。

## 复杂度分析
- 时间复杂度: O(n log n)，找中点 + 归并每层 O(n)，共 log n 层
- 空间复杂度: O(log n)，递归调用栈

## 代码评价
- 优点:
  - 满足题目核心的 O(n log n) 时间要求；找中点写法（`while(r->next){l=l->next; r=r->next; if(r->next) r=r->next;}`）正确，对 3/4 节点链表的切分都验证无误
  - 样例 `[-1,5,3,4,0]` 手动推演排序结果正确
- 可改进之处:
  - **合并风格不一致**：首节点用 `new ListNode(...)` 拷值新建，后续又直接复用原节点 `h->next = l`——结果正确但让人困惑，建议统一用"哑结点 + 纯穿链"，不新建任何节点
  - 基准情况 n==2 单独新建两个节点会把原节点"弄丢"（小内存泄漏），其实交给通用递归即可
  - 快慢指针那段两步一跳读起来绕，用 `fast=head->next` 起跳能省去 `if(r->next)` 的兜底分支
  - 循环内大量 `h=h->next` 建议并入赋值式 `h = h->next = 节点`
- 代码风格: 整体可读，若能把"找中点/合并/基准"三个职责彻底分开会更清爽

## 总结
> 归并排序主干正确、复杂度达标，主要收获应在"合并统一成哑结点穿链 + 消除多余基准分支"的整洁化改造。
