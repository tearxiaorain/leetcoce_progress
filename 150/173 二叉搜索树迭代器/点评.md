# 173. 二叉搜索树迭代器 — 代码点评

## 使用的方法
**构造时一次中序展开**：构造函数里递归中序遍历整棵树，把节点**指针**按升序压进 `vector<TreeNode*> vec`，用下标 `c`（初值 -1）记录位置；`next()` 先 `c++` 再返回 `vec[c]->val`，`hasNext()` 判断 `c + 1 < nums`。

## 复杂度分析
- 时间复杂度: 构造 O(n)，`next()` / `hasNext()` O(1)
- 空间复杂度: O(n)（存 n 个节点指针，约 8n 字节）

## 代码评价
- 优点:
  - 实现正确、语义直观：BST 的中序序列就是升序序列，取"下一个最小值"退化成数组下标自增
  - 下标起点与边界配合无误：`c = -1` 时 `hasNext()` 判断 `c + 1 < nums` 正好覆盖空树与单节点
  - `next()` / `hasNext()` 都是严格 O(1)，没有任何隐藏开销
- 可改进之处:
  - **空间不满足题目要求**：题目进阶要求 O(h)，这里一次性存下整棵树是 O(n)；改用"显式栈模拟中序"（构造时把左链压栈，`next()` 弹栈后把该节点右子树的左链继续压栈）即可做到 O(h) 且 `next()` 均摊 O(1)（见题解解法二）
  - 存 `TreeNode*` 不如直接 `push_back(root->val)` 存 `int`：只需要值，指针占的内存翻倍
  - 成员 `vec / c / nums` 全在 public 区，外部可以随意改动迭代器状态，建议放进 private
  - `nums` 这个名字容易误读成"数值数组"，实际含义是节点个数，建议 `total` / `cnt`
  - 构造函数里的 `c = -1; vec.clear();` 对新构造的对象是多余动作，直接靠成员默认值即可
  - `nums = vec.size()` 把 `size_t` 赋给 `int`，建议加 `(int)` 显式转换
  - `midorder` 是递归实现，若担心深树递归栈可以改成迭代版；另外可加一行注释说明调用约定（`next()` 应在 `hasNext()` 为真时调用），或加 `assert`
- 代码风格: `c / nums / vec` 命名信息量偏低，建议 `idx / total / nodes`

## 总结
> 中序展开 + 下标自增的实现简洁正确、`next`/`hasNext` 均为 O(1)，AC；若想命中题目"空间 O(h)"的要求，把数组换成显式栈（按需压左链）即可，顺带把成员私有化、指针改存 int。
> AC ✓
