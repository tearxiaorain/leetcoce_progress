# 27. 移除元素 — 代码点评

## 使用的方法
首尾双指针 + 交换消除。使用首指针 `i` 和尾指针收缩策略，`count` 记录已移除元素个数。当 `nums[i] == val` 时，与数组末尾元素 `nums[n-1-count]` 交换并增加 count，内层 while 循环处理连续遇到 val 的情况。

## 复杂度分析
- 时间复杂度: O(n)，每个元素最多被处理一次（虽然存在 while 内循环，但每个元素最多被交换一次）。
- 空间复杂度: O(1)，原地交换，只使用常数额外空间。

## 代码评价
- 优点: 使用了首尾指针的优化思路，当 val 元素较少时赋值次数比快慢指针法更少。
- 可改进之处: 
  1. **存在 bug**：返回值应为 `n - count`（剩余元素个数），但代码返回的是 `count`（移除元素个数）。例如 nums=[1], val=1 时，count=1，返回 1 而非正确的 0。
  2. while 内循环的嵌套逻辑过于复杂——`swap(nums[i], nums[n-1-count])` 后 `count++` 和 `i` 不变，加上 `i + count >= n` 的 break 条件，整体可读性差。
  3. 同样存在死代码问题（`return count;` 后的 for 循环），应清理。
  4. 应抽取为独立函数而非全部写在 main 中。
  5. 被注释掉的 `cin>>val` 应清理。
- 代码风格: 逻辑复杂度较高，嵌套 while 降低了可读性；存在 bug 和死代码。

## 总结
> 首尾交换的思路正确，但实现有返回值 bug（返回 count 应为 n-count），且嵌套逻辑可以大幅简化。建议使用标准的快慢指针或简化版首尾指针。
> 有 bug，需修正返回值
