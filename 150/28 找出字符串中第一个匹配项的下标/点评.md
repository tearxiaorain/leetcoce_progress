# 28. 找出字符串中第一个匹配项的下标 — 代码点评

## 使用的方法
暴力匹配。遍历 haystack 每个可能的起始位置，遇到与 needle 首字符匹配的位置时进入内层循环逐字符比较，全部匹配则返回起始下标。

## 复杂度分析
- 时间复杂度: O(m * n)，m = haystack 长度，n = needle 长度。最坏情况下每次内层循环都比较到最后一个字符才发现不匹配。
- 空间复杂度: O(1)，只使用常数额外空间。

## 代码评价
- 优点: 暴力匹配的思路简单直接，对于小规模输入足够。
- 可改进之处: 
  1. **存在 off-by-one bug**：外层循环条件 `i < n1 - n2` 应为 `i <= n1 - n2`。当 needle 恰好出现在 haystack 末尾时（如 haystack="A", needle="A"），`i < 0` 不成立，直接跳过循环返回 -1，导致错误。当前 main 中的测试 `strStr("A", "A")` 恰好暴露此问题。
  2. 变量 `flag` 赋值后从未被使用，属于冗余变量。
  3. 内循环的 flag0 变量名不够语义化，建议改为 `mismatch`。
  4. 当 needle 为空字符串时未处理（题目要求返回 0）。
  5. 可以提取为独立函数（已做），但 main 中的无关代码（vector<string> strs 等）属于从其他测试复制来的残留。
- 代码风格: 缩进和结构基本规范，但有未使用变量和残留代码。

## 总结
> 暴力匹配思路正确，但循环边界 off-by-one 导致末尾匹配失败，且存在冗余变量。建议改进边界条件或学习 KMP 实现线性时间匹配。
> 有 bug，循环条件需改为 <=
