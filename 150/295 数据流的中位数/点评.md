# 295. 数据流的中位数 — 代码点评

## 使用的方法
**双堆（大顶堆 + 小顶堆）**：`big_pq`（`cmp2`，a<b → 大顶堆）存较小一半，`small_pq`（`cmp1`，a>b → 小顶堆）存较大一半；`addNum` 依当前计数差与数值大小在两个堆之间分配或搬移堆顶，保持两半大小差 ≤1 且 `big` 堆顶 ≤ `small` 堆顶；`findMedian` 按奇偶取单堆顶或两堆顶均值。`cnt_small/cnt_big` 记录两侧数量。

## 复杂度分析
- 时间复杂度: addNum O(log n)，findMedian O(1)
- 空间复杂度: O(n)

## 代码评价
- 优点:
  - **方法正中靶心**：双堆维护"大小两半交界处即中位"，addNum O(log n)、findMedian O(1)，是本题标准最优结构；多个分支/搬移堆顶的写法能维护不变量，样例与常规序列正确（含偶数取均值）
  - 拆成 `cmp1/cmp2` 两个比较器，语义较清晰
- 可改进之处:
  - **命名严重误导，可维护性差**：`small_pq` 实际存的是"较大的一半"，`cnt_small/cnt_big` 与真正堆的大小**错位**（例如首元素进 `big_pq` 却 `cnt_small++`），读代码者极易把"小半/大半"和计数关系搞反。堆按"大顶堆存小半、小顶堆存大半"命名、计数改用堆的 `.size()`，能直接消除这类隐患
  - **分支结构过繁**：4 条 addNum 分支手写堆顶搬运，等价于标准三步——①`num <= big.top()` 进小半否则进大半；②若 `big.size() < small.size()` 挪 `small.top()` 到 `big`；③若 `big.size() > small.size()+1` 挪 `big.top()` 到 `small`。两三个判断即可，还不依赖数值均值
  - **相等分支用 `(big.top()+small.top())/2` 作整数阈值**：先算均值再拿 `num` 比大小，概念上绕、还可能受整数除法舍入影响；直接用 `num` 与小半堆顶（`big.top()`）比较决定进哪堆更稳
- 代码风格: 正确但分支多、命名反直觉，建议重构为标准三步版

## 总结
> 双堆思路与复杂度正确，常规序列均 AC；建议改用标准三步式（比大顶堆顶定去留 + 两堆 `.size()` 平衡 + 挪堆顶），并把堆命名改回"存小半 = 大顶堆"，逻辑会直观得多、不易写错。
> AC ✓
