# 236. 二叉树的最近公共祖先 — 代码点评
## 使用的方法
记录路径（方向编码）。用 `preorder`（实为 DFS 路径搜索）分别求「根 → p」「根 → q」的路径，路径用 0（左）/ 1（右）方向编码存入 `vector<int>`；再求两条路径的最长公共前缀，沿 `root` 按该前缀逐层下走，最终节点即 LCA。

## 复杂度分析
- 时间复杂度：O(n)。两次路径搜索各 O(n)（最坏遍历整棵树），求公共前缀 O(h)、沿前缀下走 O(h)，合计 O(n)。
- 空间复杂度：O(h)。两个方向编码数组 `sp`/`sq` 各 O(h)（路径长度 = 树高），递归栈 O(h)；最坏（链状树）退化为 O(n)。

## 代码评价

**优点**：
- 思路正确且直观：求两节点路径 → 最长公共前缀 → 沿前缀下走到 LCA，等价于"记录路径"的标准解法。
- 用 0/1 方向编码代替存储节点指针，节省了指针数组的空间开销。
- `flag` 用于在找到目标后立即回溯，配合 `if(flag) return;` 能保留已入栈的正确路径段（找到后不再 pop 该段），逻辑成立。

**可改进**：
- 函数名 `preorder` 与实际"路径搜索"逻辑不符，易误导。
- 方向编码 + `flag` 剪枝 + push/pop 的组合较绕，容易出错。标准"记录路径"写法是递归返回 bool 并回溯（见题解解法三）；更简洁的是递归分治（见题解解法一），单次遍历、O(n)/O(h)，无需两次搜索和三个 vector。
- 两次遍历 + 三份 vector（`sp`/`sq`/`s`）开销偏大，不如解法一一次递归分治直接。
- 第 62 行残留注释 `//sp = sq = "";`、`flag` 在两次调用间被重置，语义依赖全局突变，可读性较差。
- 头文件包含了一些未使用的 `<map>`、`<set>`、`<string>`、`<unordered_map>`、`<algorithm>`（实际用到 `<iostream>`、`<vector>`）。

**风格**：
- ACM 风格，`using namespace std;`。
- 方向编码 0/1 缺少常量命名（如 `LEFT`/`RIGHT`），可读性一般。

## 总结
> AC ✓

代码结果正确，采用"记录路径（方向编码）+ 最长公共前缀"思路，复杂度 O(n)/O(h)。主要不足是函数命名误导、三份 vector 与两次遍历开销偏大、编码方式较绕。最优为递归分治 O(n)/O(h)，一次遍历即可。
