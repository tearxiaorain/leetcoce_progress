# 274. H 指数 — 代码点评

## 使用的方法
先升序排序，然后从候选值 `t = n` 往下试：对每个 `t`，检查升序数组中**最大的 t 个元素**（下标 `n-t .. n-1`）是否都 `≥ t`，是则直接返回 `t`。等价于"是否存在至少 t 篇论文引用 ≥ t"。

## 复杂度分析
- 时间复杂度: O(n²) 最坏（排序 O(n log n)，之后每个候选 `t` 都要线性验证一次，从 n 一路试下来近似 O(n²)）
- 空间复杂度: O(1)（原地排序；系统栈忽略）

## 代码评价
- 优点:
  - 思路正确且验证充分：8 组样例 + 3000 组随机对拍与暴力一致
  - 排序后从 `n` 往下取**第一个**满足的 `t`，天然返回最大 h；`t=0` 兜底（如 `[0]` 返回 0）边界正确
- 可改进之处:
  - **验证段可 O(n) 一次完成**：排序后只需扫一遍找第一个 `citations[i] >= n-i` 的位置，`h = n-i`，不用为每个候选 t 重新线性扫（当前写法排序后还要 O(n²)，数据一大就会超时）
  - 也可用计数桶 O(n) 免排序：引用超过 n 的按 n 计，从高往低累加论文数，第一个 `total>=x` 的 x 即答案
  - 变量 `t`、`flag` 命名随意；内层 `for(i<t)` 判断 `citations[n-t+i]<t` 表达"最大的 t 篇是否都够"可以，但不如直接基于下标推导直白
- 代码风格: 排序部分 OK，判断逻辑偏绕、且复杂度没做到排序后应有的 O(n)

## 总结
> 正确（样例 + 随机对拍全过），但**排序后仍 O(n²) 验证是明显冗余**；排序后单次线性扫描即可（找 `citations[i] >= n-i`），或改用计数桶做到 O(n)。
