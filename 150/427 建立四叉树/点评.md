# 427. 建立四叉树 — 代码点评

## 使用的方法
递归四等分：`construct(grid)` 先处理边长 1 的叶子；否则把矩阵**拷贝**成 4 块子矩阵 `grid1~grid4` 分别递归建树；若四个孩子都是叶子且值相等则合并成一个叶子，否则返回值为 `-1`（即 true）的非叶节点。

## 复杂度分析
- 时间复杂度: O(n² log n)，每层每个元素被复制进子矩阵一次，共 log n 层
- 空间复杂度: O(n²)，各层持有的子矩阵拷贝峰值（约 4/3·n²）+ 递归栈

## 代码评价
- 优点:
  - 逻辑正确：`isLeaf` 与 `val` 的合并判断"四孩子全叶且值相同 → 上提为叶"恰好等价于题目"该区域同值则不再细分"，与 LeetCode 期望一致
  - 构造与节点 API 完全匹配，类型定义复用清晰
- 可改进之处:
  - **避免拷贝矩阵**：把四个子矩阵在每一层都复制一遍，时间和空间都很浪费。改成传 `(x, y, len)` 坐标 + 边长，仅靠索引在原 `grid` 上切块即可，无需任何拷贝
  - 可加**同值判定剪枝**：进入前先确认当前区域非全同值才切分；或预计算二维前缀和，使每块的同值判定从 O(len²) 降到 O(1)，整体可到 O(n²)
  - 非叶节点 `new Node(-1, false, ...)` 用 `-1` 表示"值无所谓"，可读性差（`bool` 会转成 true 但读者要猜），显式传 `true/false` 或注释说明
  - `vector<int> t; grid1.push_back(t);` 的初始化写法可简化为在循环里直接构造
- 代码风格: 结构对称易读，属"能跑但对复杂度无感"的写法，建议往坐标递归方向改

## 总结
> 合并判定思路正确，最大短板是**逐层拷贝子矩阵**。改成坐标 + 边长递归（必要时前缀和判同值），时间空间都能大幅改善。
