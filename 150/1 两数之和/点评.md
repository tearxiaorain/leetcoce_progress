# 1. 两数之和 — 代码点评

## 使用的方法
**哈希表**（`std::map`）。遍历数组时，将 `target - nums[i]` 作为 key、当前下标作为 value 存入 map，后续元素在 map 中查找自身是否命中某个 key。

## 复杂度分析
- 时间复杂度: **O(n log n)** — `std::map` 基于红黑树，`find` / `insert` 各 O(log n)，共 n 次操作
- 空间复杂度: **O(n)** — map 存储最多 n 个元素

> ⚠️ 若改用 `unordered_map`，时间复杂度可优化到 **O(n)**（平均）。当前使用 `map` 比最优解慢了一个对数因子。

## 代码评价

### 优点
- 核心思路正确：存储差值、单次遍历查找，避免了暴力 O(n²)
- `find` 判断是否存在再取值，逻辑清晰
- 有 `break` 确保找到后立即退出

### 可改进之处
1. **`std::map` → `std::unordered_map`**: 本题无需有序性，用 `unordered_map` 可将查找/插入从 O(log n) 提升到 O(1)
2. **冗余变量 `flag`**: 定义了 `int flag=0` 并自增但从未使用，应删除
3. **`vector<int> res(0)`**: 直接写 `vector<int> res` 即可，`(0)` 多余
4. **`main` 测试代码有错误**: `twoSum` 接受 `vector<int>&`，但传入了 `vector<string>`，编译不过；测试代码未实际验证结果

### 代码风格
- 命名简洁（`m`, `n`, `res`），对于短函数可接受
- 缩进、括号风格一致
- 建议将 `using namespace std` 替换为显式 `std::` 前缀（工程习惯）

## 总结
> 哈希表思路正确，实现有小瑕疵（map 而非 unordered_map、死代码、测试代码错误）。整体思路没问题，优化空间在于选对数据结构和清理无用代码。
