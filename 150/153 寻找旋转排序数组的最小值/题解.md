# 153. 寻找旋转排序数组的最小值

## 题目描述

> 已知一个长度为 `n` 的数组，预先按照升序排列，经由 `1` 到 `n` 次 **旋转** 后，得到输入数组。例如，原数组 `nums = [0,1,2,4,5,6,7]` 在变化后可能得到：
> - 若旋转 4 次，则可以得到 `[4,5,6,7,0,1,2]`
> - 若旋转 7 次，则可以得到 `[0,1,2,4,5,6,7]`
>
> 注意，数组 `[a[0], a[1], a[2], ..., a[n-1]]` **旋转一次** 的结果为数组 `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`。
> 给你一个元素值 **互不相同** 的数组 `nums`，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 **最小元素**。
> 你必须设计一个时间复杂度为 **O(log n)** 的算法解决此问题。

## 解法一: 二分查找（最优解）

### 思路
旋转排序数组的核心性质：将数组一分为二后，至少有一半是有序的，最小值一定在"无序"的那一半中。

具体做法：使用二分查找，比较 `nums[mid]` 与 `nums[right]`：
- 若 `nums[mid] < nums[right]`：说明 `[mid, right]` 这一段是升序的，最小值在左半部分（包括 `mid`），令 `right = mid`
- 若 `nums[mid] > nums[right]`：说明旋转点（最小值）在 `[mid+1, right]` 范围内，令 `left = mid + 1`

当 `left == right` 时，该位置就是最小值。

### 复杂度
- 时间复杂度: **O(log n)** —— 标准的二分查找，每次将搜索范围减半
- 空间复杂度: **O(1)** —— 仅使用常量额外空间

### 代码
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[right]) {
                // 右半部分有序，最小值在左半部分（含mid）
                right = mid;
            } else {
                // 右半部分无序，最小值在右半部分
                left = mid + 1;
            }
        }
        return nums[left];
    }
};
```

## 解法二: 线性扫描

### 思路
遍历数组，找到第一个满足 `nums[i] > nums[i+1]` 的位置，则 `nums[i+1]` 即为最小值。若遍历结束未找到这样的位置，说明数组未被旋转（或旋转了 n 次），最小值为 `nums[0]`。

### 复杂度
- 时间复杂度: **O(n)** —— 最坏情况下需要遍历整个数组
- 空间复杂度: **O(1)** —— 仅使用常量额外空间

### 代码
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        for (int i = 0; i < nums.size() - 1; i++) {
            if (nums[i] > nums[i + 1]) {
                return nums[i + 1];
            }
        }
        return nums[0];
    }
};
```

## 总结

| 解法 | 时间复杂度 | 空间复杂度 | 优点 | 缺点 |
|------|-----------|-----------|------|------|
| 二分查找 | O(log n) | O(1) | 时间最优，满足题目要求 | 需要理解旋转数组性质 |
| 线性扫描 | O(n) | O(1) | 代码简单直观 | 时间复杂度不满足题目 O(log n) 要求 |

二分查找法是本题的最优解，充分利用了旋转排序数组"部分有序"的性质，将搜索范围每次折半，达到 O(log n) 的时间复杂度。注意与 `nums[right]` 比较而非 `nums[left]` 比较，因为当数组完全有序（未旋转）时，`nums[mid] > nums[left]` 会导致误判。
