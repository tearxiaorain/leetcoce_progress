# 153. 寻找旋转排序数组的最小值 — 代码点评

## 使用的方法

用户使用**非标准二分查找**的思路：在 while 循环中比较 `nums[mid]` 与 `nums[left]` 和 `nums[right]`，试图定位旋转点。循环中有两个退出条件：(1) 不满足两个比较条件时 break；(2) 当 `nums[mid] > nums[(mid+1)%n]` 时提前 break（检测峰值）。循环结束后通过 `mid` 位置与相邻元素的比较确定最小值下标。

本质上是在二分搜索中寻找"下降点"（即 `nums[i] > nums[i+1]` 的位置），`nums[(i+1)%n]` 即为最小值。

## 复杂度分析
- 时间复杂度: **O(log n)** — while 循环在大多数情况下每次折半搜索空间，符合二分查找特征；但非标准比较逻辑可能在特定输入下导致提前退出而非精确收敛
- 空间复杂度: **O(1)** — 仅使用常量额外空间

> 最优解法: O(log n) O(1) 标准二分查找（仅比较 `nums[mid]` 与 `nums[right]`）。

## 代码评价

### 优点
- 整体思路正确：利用二分查找而非暴力 O(n) 扫描，时间复杂度达到题目要求的 O(log n)
- 尝试在循环中检测"下降点"（`nums[mid] > nums[(mid+1)%n]`）提前退出，有一定优化意识
- 代码简洁，额外空间 O(1)

### 可改进之处
1. **二分逻辑不标准，存在潜在 bug**: 比较 `nums[mid] > nums[left]` 和 `nums[mid] < nums[right]` 两个条件，当数组完全有序（未旋转）时，`nums[mid] > nums[left]` 始终为 true（基于部分情况），会导致 `left` 不断右移，依赖 else break 和循环后修正逻辑来兜底——路径过于迂回
2. **标准解法只需比较 `nums[mid]` 与 `nums[right]`**: 
   - `nums[mid] < nums[right]` → 最小值在 `[left, mid]`，`right = mid`
   - `nums[mid] > nums[right]` → 最小值在 `[mid+1, right]`，`left = mid + 1`
   简洁清晰且不会误判
3. **循环后修正逻辑脆弱**: 用 `k = mid` 后与 `nums[(k+1)%n]` 比较再修正，依赖循环退出时的 `mid` 值恰好接近目标——不如标准二分在 `left == right` 时自然收敛
4. **`mid` 初始化冗余**: 循环前 `int mid = right / 2` 在循环体内被立即覆盖，无实际作用
5. **`else break` 过于粗糙**: 当 `nums[mid] == nums[left]` 或 `nums[mid] == nums[right]`（搜索范围缩小到相邻元素时）直接 break，可能导致未找到真正的最小值（尽管修正逻辑可能挽回）
6. **测试数据有误**: `arr` 的前两个元素 `{6,5}` 不是旋转排序数组（`5,6` 旋转后应为 `[6,5]` 或 `[5,6]`，但原始数组必须是升序的；若原始为 `[5,6]` 旋转一次得 `[6,5]` 合法；但 main 只 push 了 2 个元素 `i<2`）

### 代码风格
- 变量命名清晰（`left`, `right`, `mid`, `n`）
- 缩进和括号风格一致
- 建议移除循环前的 `mid` 初始化、清理注释掉的测试代码

## 总结
> 二分查找思路方向正确，但实现偏离了标准模板，导致逻辑迂回且存在边界隐患。建议采用标准的"仅与右端点比较"的二分模式，简洁可靠。整体时间复杂度满足 O(log n) 要求，但代码健壮性有待提升。
