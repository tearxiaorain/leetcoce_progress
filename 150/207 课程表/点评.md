# 207. 课程表 — 代码点评

## 使用的方法
**邻接矩阵 + 双标记递归 DFS 判环**：`graph[a][b] = 1` 表示"修 a 前需先修 b"（有向边 a → b）。`flag` 记录"该点已彻底搜完"，`pathf` 记录"该点在当前递归路径上"。`dfs(c)` 先看 `f`（全局已发现环）、再看 `pathf[c]`（回到路径上的点 → 有环），否则标记 `pathf[c] = 1`、遍历所有 `graph[c][i] && !flag[i]` 的邻居递归，最后 `flag[c] = 1`。外层对所有 `!flag[i]` 的点各做一次 DFS，发现环立即返回 false。

## 复杂度分析
- 时间复杂度: O(V²)（邻接矩阵的构建与每个点的邻居扫描都是 O(V)，V = numCourses；与边的数量无关）
- 空间复杂度: O(V²)（V×V 的 int 矩阵，V = 2000 时约 16 MB）+ O(V) 递归栈

## 代码评价
- 优点:
  - 判环思路正确：`pathf` 相当于三色标记里的"在栈上"，一旦第二次进入路径上的点就说明有环，用 `f` 标志立刻剪掉整棵搜索树，不会白跑
  - `graph` 改为传引用之后不再每层拷贝矩阵，这正是之前"超内存"的根因，注释里也把这一点记下来了，是一次有效的修复
  - 外层 `if (!flag[i])` 保证每个连通块只被搜一遍；已有环时 `if (f) return false;` 提前结束，不做无用搜索
  - 空先修关系（`numCourses` 个孤立点）和自环类退化输入都能正确返回
- 可改进之处:
  - **邻接矩阵是这份代码最大的结构性问题**：V = 2000 时要开 16 MB 的 `vector<vector<int>>`，且每个点的邻居判断都要扫过整行 O(V)，总时间 O(V²)。换成邻接表（只存真实存在的边）即为标准的 O(V + E) 时间 / O(V + E) 空间，这也是"超内存"最容易复发的地方
  - **`pathf` 从不复位**：现在能过是因为"只对 `!flag` 的点递归 + 结束时设 `flag`"这两条恰好保证不会重入已完成点，属于侥幸成立；"在路径上"本应是可回退的状态，规范做法是在 `dfs` 返回前写 `pathf[c] = 0;`，或者干脆用一个 `vector<int> color`（0/1/2）替代两个数组。注释里那段被注释掉的复位循环是方向不对的补救，建议直接删掉
  - 环标记 `int &f` 贯穿整个递归：让 `dfs` 直接返回 `bool`（false 表示发现环）更直观，也少传一个参数
  - `if (!f) return true; return false;` 可直接写 `return !f;`；`canFinish` 里的 `if (f) return false;` 与末尾返回值也有重复
  - `main` 里的测试数据只造出 1 条边（`int arr[2][2] = {0, 1, 1, 0}` 且只读第一行），自测覆盖太薄；建议补 `[[1,0],[0,1]]`（有环 → false）、`[[1,4],[2,4],[3,1],[3,2]]`（无环 → true）这两个官方用例
  - 顶部注释"超内存"是历史问题记录，修复后建议改成说明当前实现（传引用、邻接表可优化）
- 代码风格: `dfs` 的参数 `c / f / flag / pathf` 太简，建议 `cur / cycleFound / visited / onPath`；`flag` 与 `pathf` 作用相似容易混，用 `color` 语义更清楚

## 总结
> 判环逻辑正确、把 `graph` 改成引用解决了超内存、AC；结构性改进是"邻接表 + 单张三色数组（退出时复位）"，把 O(V²) 时间和空间降到 O(V+E)，并补上有环用例做自测。
