# 221. 最大正方形 — 代码点评

## 使用的方法
**动态规划**：`dp[i][j]` 表示以 `(i,j)` 为右下角的最大全 1 正方形边长。先单独初始化第 0 行、第 0 列（值为 1 则 dp=1），再自左上向右下填表：当 `matrix[i][j]=='1'` 时，若左上、上、左三个邻居相等则边长 `+1`，否则取三者最小值再 `+1`；全 0 格子 dp=0。答案取所有 dp 最大值平方。

## 复杂度分析
- 时间复杂度: O(mn)
- 空间复杂度: O(mn)

## 代码评价
- 优点:
  - **方向正确、AC**：dp 递推 + 边界单独初始化，逻辑上覆盖了"短板决定边长"这一核心；复杂度 O(mn) 达标
  - 首行首列抽出单独初始化，规避了 dp 数组越界，思路清楚
- 可改进之处:
  - **求"三邻取小"的分支写得太绕**：`dp[i][j] = min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1` 一行即可。当前版本用 `if...else` 链手动比大小，其中第二处 `if (dp[i][j-1] < dp[i-1][j])` 是拿 `dp[i][j-1]` 去比 `dp[i-1][j]`（而非已选出的当前最小值），代码只有在 DP 值满足"相邻格边长差 ≤1"时才恰好等价于取 min——**对非法的假设很敏感，容易在改动时踩坑**
  - 用 `dp` 多开一圈（`m+1 × n+1`）就不必单独初始化首行首列，主循环从 1 开始即可，代码更统一
  - 变量名 `max` 遮蔽了 `<algorithm>` 的 `std::max`；虽然手写比较没冲突，改名 `best` 更安全
- 代码风格: 正确但 min 逻辑可读性差，建议收敛成一行 min

## 总结
> DP 思路与复杂度正确、AC；建议把三邻取小压缩成 `dp[i][j] = min({三个邻居}) + 1`，并可加一圈哨兵消除首行首列特判，逻辑与可读性都更好。
> AC ✓
