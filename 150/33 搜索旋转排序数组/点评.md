# 33. 搜索旋转排序数组 — 代码点评

## 用户算法概述

用户尝试使用"先找旋转点，再分段二分"的两阶段策略：先通过二分定位数组中的最大值（旋转点 `k`），然后根据 target 与 `nums[0]` / `nums[n-1]` 的关系决定在 `[0, k]` 还是 `[k+1, n-1]` 中做标准二分查找。

## 用户复杂度分析

- 时间复杂度：O(log n)（意图）— 两个二分阶段，每阶段 O(log n)
- 空间复杂度：O(1)

## 代码中存在的问题

### 1. 旋转点查找逻辑有误（核心 Bug）

```cpp
while (left <= right)
{
    mid = (left + right) / 2;
    if (nums[mid] > nums[left])
        left = mid + 1;
    else if (nums[mid] < nums[right])
        right = mid - 1;
    else break;
    if (nums[mid] > nums[(mid + 1) % n])
        break;
}
```

这段寻找旋转点（最大值）的逻辑存在问题。以 `[4,5,6,7,0,1,2]` 为例：

- 初始 `left=0, right=6, mid=3`（值 7）
- `nums[3]=7 > nums[0]=4`，执行 `left=4`
- 现在 `left=4, right=6`，但 left 已经跳到了右半区（值 0），最大值 7 的位置 3 被跳过

**正确做法**：找最小值应该用 `nums[mid] > nums[right]` 判断；找最大值同理需要调整比较对象。用 `nums[mid] > nums[left]` 来判断在旋转数组中没有稳定含义。

### 2. 多余的 k 修正逻辑

```cpp
if (nums[k] < nums[(k + 1) % n])
    k = (k + 1) % n;
```

这行代码试图修正 k 的位置，但 `(k+1)%n` 可能绕回数组头部，且该修正本身说明前面的旋转点查找不可靠。

### 3. 边界条件处理不够严谨

```cpp
if (nums[k] < target) return -1;
if (nums[(k + 1) % n] > target) return -1;
```

这两行试图提前判断 target 是否在有效范围内，但逻辑不够完整：
- k 是最大值下标，`nums[k]` 是最大值，小于最大值的 target 完全可能存在
- `nums[(k+1)%n]` 是最小值，大于最小值的 target 也可能存在
- 实际应该判断 target 是否在 `[最小值, 最大值]` 范围内

### 4. 测试用例不足

`main()` 中只测试了 `{6,5}` 查 5，且数组声明为 9 个元素但只用了 2 个。这远不足以覆盖各种旋转情况。

### 5. 不必要的头文件

引入了 `<stack>`, `<map>`, `<set>`, `<string>`, `<unordered_map>` 等未使用的头文件。

## 建议改进

1. **旋转点查找**：使用标准二分模板 `nums[mid] > nums[right]` 来判断 mid 位于左半区还是右半区
2. **一次二分法**：更推荐不显式找旋转点，直接在二分中判断有序半区（见题解解法二），代码更简洁且无边界问题
3. **增加测试**：覆盖未旋转、单元素、target 在左半区/右半区/不存在等场景
