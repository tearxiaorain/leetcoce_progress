# 210. 课程表 II — 代码点评

## 使用的方法
**邻接矩阵 + 入度数组的 Kahn 拓扑排序**：`g[b][a] = 1` 表示"先修 b 再修 a"，`incount` 记入度。每轮从头线性扫描、取第一个"入度为 0 且还没输出"的课程放进 `res`，标记 `flag`，再把它的后继入度减 1；循环 n 轮后如果 `res.size() != numCourses`，说明有环，返回空数组。

## 复杂度分析
- 时间复杂度: O(V²)（建矩阵 O(V²)；每轮扫描 O(V) + 递减后继 O(V)，共 V 轮，边的信息只在建表时用到）
- 空间复杂度: O(V²)（V×V 的 int 邻接矩阵，V = 2000 时约 16 MB）+ O(V)

## 代码评价
- 优点:
  - **拓扑序语义正确**：只有入度被减到 0 的课程才会入队，因此输出的顺序一定合法；每轮取"当前编号最小的可修课程"，属于合法顺序中的一种
  - 有环的判定简单有效：无环时每轮必能取出一个点，n 轮刚好取满 n 个；有环时取不满，靠 `res.size() != numCourses` 收口
  - `res.clear()` 返回空数组的收尾干净，与题目要求一致
- 可改进之处:
  - **邻接矩阵 + 每轮全表扫描**是这份代码的主要瓶颈：V = 2000 时要开 16 MB 矩阵，且内层扫描 + 递减共约 800 万次操作。换成**邻接表 + 队列**（标准 Kahn）就是 O(V + E) 时间 / O(V + E) 空间，代码还更短（见题解解法一）
  - **重复先修关系会导致误判**：入度按 `prerequisites` 逐条累加（重复对会加两次），而减入度是按矩阵格子 `g[j][k]` 只减一次；若同一对 `[a, b]` 出现两次，`a` 的入度永远降不到 0，最终被当成"有环"返回空数组。本题约束保证先修对互不相同，所以能过，但这是真实存在的隐患——用邻接表就自然避免了
  - 内层 `break` 之后又要在下一轮重扫整张表，等于每输出一个点多花 O(V)；队列写法可以把这部分开销完全消掉
  - 有环时外层仍会白跑完 n 轮（每轮 O(V) 扫描），可以加"本轮没找到候选就提前退出"的判断
  - `flag` 与 `res.size()` 有信息重叠（`flag` 仍需保留，因为 `res` 的顺序不等于编号顺序），但可以合并成一个"是否已输出"的 `bool` 数组，语义更明确
  - `main` 里没有任何测试用例（只输出 `1`），建议至少跑 `[[1,0]]`（→ `[0,1]`）和 `[[1,0],[0,1]]`（→ 空数组）两组；`#include <math.h>` 未使用
- 代码风格: `g / incount / flag / res` 命名尚可，但矩阵方向约定（`g[b][a] = 1` 表示 b 是先修）建议写一行注释，否则很容易读反

## 总结
> Kahn 拓扑排序的思路与"输出数量不足即有环"的判定都正确、AC；把邻接矩阵换成邻接表 + 队列可把 O(V²) 时间与 16 MB 内存降到 O(V+E)，同时天然消除"重复先修对导致误判有环"的隐患。
> AC ✓
