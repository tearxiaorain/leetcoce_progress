# 23. 合并K个升序链表 — 代码点评

## 使用的方法
**分治两两合并**：`mergeKLists` 把链表数组对半拆成 `m1/m2` 两组，各自递归合并后，再用 `merge`（21 题的归并）把两条结果合成一条。对 `n==0`（返回空）、`n==1`（直接返回该条）做了特判。未用堆。

## 复杂度分析
- 时间复杂度: O(N log k)（N 为总节点数，k 为链表数；每层节点参与一次合并）
- 空间复杂度: O(log k) 递归栈 + 每层为拆分临时复制的指针数组（沿递归路径合计 O(N) 的 vector 开销）

## 代码评价
- 优点:
  - **正确性扎实**：除了手工样例（`[[1,4,5],[1,3,4],[2,6]]` → `[1,1,2,3,4,4,5,6]`、空数组、单链表）外，跑了 **200 轮随机多链表交叉验证**，与"全部展开后排序"的结果完全一致
  - 选分治而不是顺序合并，避免了一条条串行合并的 O(k²N) 退化；特判 `n==1` 免去无谓递归
  - `merge` 用哨兵节点 + 复用原节点，无新建节点浪费
- 可改进之处:
  - 每层递归都拷贝一遍 `vector<ListNode*> m1/m2`，内存与拷贝有开销；可改用**下标范围递归**（传 `lists, lo, hi`）消除拷贝
  - 与分治并列的更常规解是**最小堆**：每次弹最小头并压入其 next，O(N log k) O(k)，代码更短、无需递归；两种都可，选一种为主即可
  - `merge` 形参用 `ListNode*&` 引用却从不修改原指针，可改传值，避免误以为会改动调用方
  - 递归拆分逻辑（`i + n/2` 配对 + 奇数多塞末尾）正确但稍费解，可用 `[lo,mid)`/`[mid,hi)` 的下标写法替代
- 代码风格: 结构清晰、命名可读，属质量不错的分治实现

## 总结
> 分治归并正确（手工 + 200 轮随机全过），复杂度达标；可优化点是去掉递归里的 vector 拷贝（改下标分治）或用最小堆简化实现。
