# 162. 寻找峰值 — 代码点评

> 目录名取为"162 寻找最大值"，本题即 LeetCode 162（Find Peak Element），要求返回任意一个**峰值下标**（局部最大），不是数组最大值。

## 使用的方法
**二分 + 两侧哨兵**：先把原数组复制成 `num = [INT_MIN] + nums + [INT_MIN]`，把左右边界统一成"一定比邻居小"的哨兵，再在 `[1, n]` 上递归二分——`num[mid]` 同时大于左右邻居就返回 `mid`；`num[mid] < num[mid+1]` 说明在上坡、往右半找；否则往左半找。返回值再 `-1` 映射回原数组下标。

## 复杂度分析
- 时间复杂度: O(log n)
- 空间复杂度: O(n)（每层递归都带着一份哨兵副本 `num`）+ O(log n) 递归栈

## 代码评价
- 优点:
  - **二分判据是对的**：只比较 `mid` 与 `mid+1` 就能确定峰值在左半还是右半——"上坡往右、下坡往左"的不变量在补了 `INT_MIN` 哨兵后始终成立，递归收敛处必然是峰值
  - 用哨兵代替"下标越界特判"，`num[mid-1]`、`num[mid+1]` 永远合法，省掉了边界分支
  - `n == 1` 提前返回 0，`return find(num, 1, n) - 1` 的下标映射也没写错
  - 只用 `nums[mid] < nums[mid+1]` 决定方向，是本题 O(log n) 的关键洞察，没有退化成线性扫描
- 可改进之处:
  - **不需要哨兵副本**：标准写法直接 `while (l < r)`，比较 `nums[mid]` 与 `nums[mid+1]`（`mid = l + (r-l)/2` 保证 `mid + 1 <= r <= n-1`，天然不越界），空间从 O(n) 降到 O(1)，也省掉一次 O(n) 拷贝
  - 递归可以写成循环（尾递归），进一步省掉 O(log n) 的栈
  - 进入判断 `nums[mid] > nums[mid-1] && nums[mid] > nums[mid+1]` 在哨兵版里是必要的，但等价于"只要 `nums[mid] > nums[mid+1]` 就往左收"，多比较一次左邻居属于可省略的常数开销
  - `INT_MIN` 依赖 `<iostream>` 的间接包含，建议显式 `#include <climits>`
  - 函数名 `find` 与 `std::find` 重名（又 `using namespace std`），建议改为 `findPeak` / `binarySearch`
  - 目录名"寻找最大值"与题意不符，容易在复习时误以为是"求数组最大值"，建议改名为「162 寻找峰值」
- 代码风格: 递归函数缺少一行"`[l, r]` 内一定存在峰值"的不变量注释，而这条不变量正是本解法能成立的理由

## 总结
> 二分爬坡的核心洞察抓住了、O(log n) 正确 AC；把哨兵副本换成"只比较 mid 与 mid+1"的循环写法，空间从 O(n) 降到 O(1)，并建议把目录名改为官方的"寻找峰值"。
> AC ✓
