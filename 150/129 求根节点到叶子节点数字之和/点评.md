# 129. 求根节点到叶节点数字之和 — 代码点评
## 使用的方法
自顶向下"原地改值 + 全局 vector 收集"：递归前把前缀累加到子节点上（`root->left->val += root->val * 10`），使叶子节点的值即为整条路径数字；叶子节点把值压入全局 `vector<int> nums`；每个内部节点最后对 `nums` 做一次全量求和返回。

## 复杂度分析
- 时间复杂度：O(n²)（最坏情况）。递归本身 O(n)，但每个内部节点都对全局 `nums` 做一次全量求和，梳状树（每个内部节点带一个叶子孩子）时累计为 O(n²)；平衡树约 O(n log n)。最优为 O(n)。
- 空间复杂度：O(n)，全局 `nums` 保存所有叶子节点值（O(叶子数)）+ 递归栈 O(h)，最坏 O(n)。

## 代码评价

**优点**：
- 核心的"前缀传递"思路方向正确：`child->val += parent->val * 10` 确实能把路径前缀传递到子节点，叶子处即为完整路径数字。
- 有空节点、叶子节点的边界处理，能对题目样例得到正确结果。

**可改进（关键问题）**：
- 全局 `vector<int> nums` + 每个内部节点全量求和，导致时间复杂度退化到 O(n²)，远差于最优 O(n)。递归返回值 `nl`/`nr` 在第 67-77 行被赋值却从未使用，函数实际结果完全依赖全局状态，语义混乱且不可重入。
- 依赖全局状态导致多次调用需手动清理：`main` 中第 104-107、110-113 行用 `for(...) nums[i]=0` 只是把已有元素置零而并未清空 vector，靠"零不影响求和"才侥幸正确，非常脆弱。建议每次调用前 `nums.clear()`，更优做法是彻底移除全局变量。
- 第 71、76 行原地修改树节点值（`root->left->val += ...`）破坏原树，且依赖"节点为 0~9 单个数字"的前提；前缀累加后节点值会远超 9，若题目放宽节点取值范围会出错。
- 注释掉的旧代码（第 34-54 行）与现行实现并存，增加了阅读负担。
- 头文件包含了一些未使用的 `<stack>`、`<map>`、`<set>`、`<string>`、`<unordered_map>`、`<algorithm>`（现行代码只用到 `<iostream>`、`<vector>`）。
- 标准做法：递归维护前缀 `cur = cur * 10 + node->val`，叶子处累加，O(n)/O(h)，无需全局变量、无需修改树。

**风格**：
- ACM 风格，但"全局 vector + 就地改树 + 死代码返回值"属反模式，可维护性差。

## 总结
> AC ✓

代码结果正确，但实现是反模式：全局 vector 全量求和使复杂度退化到 O(n²)，返回值 `nl`/`nr` 为死代码，就地改树破坏原结构且依赖单数字前提。建议改写为标准的"前缀传递"递归（`cur = cur*10 + val`），O(n)/O(h) 且无副作用。
