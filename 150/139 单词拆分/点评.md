# 139. 单词拆分 — 代码点评
## 使用的方法
一种非标准的前缀拼接法。构建前缀数组 `srr` 存储 s 的所有前缀 `s[0..i]`，然后对于每个位置 i，尝试找一个字典单词使得 `str[i-len] + word == srr[i]`（即用之前匹配到的字符串加上当前单词拼接出当前前缀）。使用 `str` 数组记录每个位置能否匹配以及匹配的内容。

## 复杂度分析
- 时间复杂度：O(n * k)，外层遍历 n 个位置，内层遍历 k 个字典单词。
- 空间复杂度：O(n)，需要 `srr` 和 `str` 两个字符串数组。

## 代码评价

**优点**：
- 用到了"前缀匹配"的直觉，`srr` 预先存储每个前缀避免了反复调用 `substr`。
- 代码结构清晰，思路具有独创性。

**可改进**：
- **算法存在缺陷**：该方法的逻辑是 `str[i-len] + wordDict[j] == srr[i]`，但这要求 `str[i-len]` 必须恰好等于 `srr[i-len]` 才能拼接。由于每个位置只保留一种可能的匹配方式（且 `str[i-len]` 可能是空字符串 `""` 表示不可达），当存在多种拆分方式时，可能错误地标记某些可达位置为不可达。例如 s="aaaaaaa"，dict={"aaa","aaaa"}：该算法可能漏解。
  
  具体问题在于：`str` 数组中不匹配的位置存储为空字符串，但空字符串拼接任何单词都无法等于目标前缀，导致某些本应可达的位置被阻断。
  
  标准解法应使用布尔数组 `dp[i]` 表示 `s[0..i-1]` 是否可拆分，并检查 `dp[j] && s.substr(j,i-j) in dict`。

- **未使用哈希集合优化词典查找**：直接遍历 `wordDict` 列表进行字符串拼接比较，而非先用 `unordered_set` 存储字典再 O(1) 查找，效率较低。
- **头文件冗余**：包含了 `<stack>`、`<map>`、`<set>` 等未使用的头文件。

**风格**：
- 变量命名如 `nw`（字典大小）、`srr`（前缀数组）、`t`（临时字符串）不够表意，建议用 `dictSize`、`prefixes`、`curPrefix` 等。
- 整体风格为竞赛导向的紧凑写法。

## 总结
> AC ?

算法逻辑存在潜在缺陷——使用字符串拼接比较而非布尔型 DP 状态转移，可能在某些输入下给出错误结果。建议改用标准的 `dp[i] = dp[j] && s[j..i-1] in wordDict` 递推。
