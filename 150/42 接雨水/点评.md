# 42. 接雨水 — 代码点评

## 使用的方法
**水平分层扫描（自顶向下）**。将 (高度, 索引) 排序后，从最高的柱子向最低的柱子逐层扫描。维护已处理柱子的最左索引 `d1` 和最右索引 `d2`，每下降一个高度层，计算该层可容纳的水量：

```
水量 = (已覆盖区间长度 - 已处理柱子数) * 高度差
```

核心公式 `count += (Len - len) * (h1 - h2)`，其中 `Len = d2 - d1 + 1` 是区间长度，`len` 是高度 ≥ 当前层的柱子数量。

## 复杂度分析
- 时间复杂度: O(n log n)，主要来自排序
- 空间复杂度: O(n)，存储 pair 数组

## 代码评价
- 优点: 思路新颖，不同于常规的双指针/DP/单调栈解法；从"水平切片"角度理解接雨水问题，几何直觉好
- 可改进之处:
  1. **时间复杂度偏高**: O(n log n) vs 最优 O(n)，排序是瓶颈
  2. **逻辑可读性差**: `d1/d2/n1/n2/len/Len/h1/h2` 变量名过于简略，建议用 `leftmost/rightmost/same_height_start` 等语义化命名
  3. **初始化写法奇怪**: `vector<pair<int,int>> arr(0)` 应写为 `vector<pair<int,int>> arr`
  4. **未使用的 header**: `<stack> <map> <set> <string> <algorithm>` 中仅 `<algorithm>` 用于 sort，其余可删除
  5. 当同一高度有多个柱子时，只更新 d1/d2 不计数，逻辑隐晦，缺少注释说明
- 代码风格: 缩进基本一致，但变量命名过于简短，缺少必要注释

## 总结
> 排序后自顶向下逐层计算水量的几何解法，思路独特但时间复杂度非最优，代码可读性有待提升。
