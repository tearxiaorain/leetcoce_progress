# 73. 矩阵置零 — 代码点评

## 使用的方法
**map 标记法**。用两个 `map<int, int>` 分别记录哪些行 (`mn`) 和哪些列 (`mm`) 含有 0。第一遍遍历标记，第二遍逐行置零，第三遍逐列置零。

本质上属于"额外数组标记法"的变体，用 map 代替了 vector<bool>。

## 复杂度分析
- 时间复杂度: O(m * n)。标记阶段 O(m*n)；置零阶段：每个被标记行全置零 O(r*m)，每个被标记列全置零 O(c*n)。在最坏情况 r=m, c=n 下为 O(m² + n²)，但仍不超过 O(m*n) 的常数倍（因为每个元素最多被置零两次）
- 空间复杂度: O(m + n)，两个 map 最多存储所有行列编号

## 代码评价
- 优点:
  1. 标记-置零分两阶段的思路清晰正确：先只做标记，再统一置零，避免了遍历过程中修改造成的连锁反应
  2. 逻辑正确，能处理任意位置的 0
- 可改进之处:
  1. **`map` 使用过重**: 仅需要 `set<int>` 记录行号/列号即可，不需要 key-value 对。`mn[i]=i` 的 value 完全未使用，仅是冗余存储
  2. **`find` + `insert` 模式冗余**: `mn[i] = i;` 一行即可完成插入或覆盖，不需要先 `find` 判断。当前写法 5 行可简化为 1 行
  3. **可用 `vector<bool>` 替代 map**: 用两个 vector<bool> 做标记即可，O(1) 查找和插入，比 map 的 O(log k) 更快，且代码更简洁
  4. **变量命名不直观**: `mn` 和 `mm` 难以区分含义，建议 `zeroRows` 和 `zeroCols`
  5. **置零遍历可优化**: 当前对每个标记行/列都遍历整行/整列，可先统一标记后一次遍历完成置零（检查该行或该列是否在 map 中），减少对同一元素的多次赋值
  6. **未使用的 header**: `<stack>` `<set>` `<string>` `<algorithm>` 可删除（`<map>` 在使用中）
- 代码风格: 结构清晰，缩进一致；但 `find/insert` 模式过于啰嗦

## 总结
> 标记-置零思路正确，但用 map 代替 vector<bool> 得不偿失（更慢、更占空间、代码更长）；find-then-insert 模式可精简为一行。
