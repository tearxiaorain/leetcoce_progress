# 373. 查找和最小的 K 对数字

## 题目描述

> 给定两个**升序**整数数组 `nums1`、`nums2` 和整数 `k`,定义数对 `(u, v)`,其中第一个元素来自 `nums1`、第二个来自 `nums2`。返回**和最小的 k 个数对**(升序数组,长度可达 10⁴)。有并列时按任意顺序返回即可。
> 输入输出示意:`nums1=[1,7,11], nums2=[2,4,6], k=3` → `[[1,2],[1,4],[1,6]]`。

## 解法一: 全量入堆（直观，会超内存）

### 思路
把 `n1 × n2` 个数对全部按和 push 进**最小堆**,再 pop k 次。思路最直白,但堆里要同时存下全部数对:长度各 10⁴ 时全量 10⁸ 个,空间直接爆(本题常见的 MLE 根因),时间也慢。

### 复杂度
- 时间复杂度: O(n1·n2 + k log(n1·n2))
- 空间复杂度: O(n1·n2) —— 不可取

## 解法二: K 路归并（标准解，O(k log k)）

### 思路
两个数组都升序,**不要枚举全部数对**,而是把它看成 **K 路归并**:
- 固定 `nums1` 的下标 `i`,则 `(i,0),(i,1),(i,2),…` 这一行随 `j` 单调不减(nums2 升序),是一条已排序的"流";
- 共有 `n1` 条这样的流,每条的**当前最小头**是 `(i,0)`。先把若干流头(取前 `min(n1, k)` 条即可——下标 ≥ k 的流头已 ≥ 前 k 个候选)压入**最小堆(按和)**;
- 反复 pop 堆顶 `(i,j)` 记入答案,并把同一条流的下一个 `(i, j+1)` 压回堆。

每轮堆里只有一个候选被替换成更大值,堆规模恒为 O(min(n1,k)),与 `n1·n2` 无关。

### 复杂度
- 时间复杂度: O(k log(min(n1,k)))(k 次堆操作)
- 空间复杂度: O(min(n1,k))

### 代码
```cpp
struct Cmp {
    bool operator()(const tuple<int,int,int>& x,
                    const tuple<int,int,int>& y) const {
        return get<0>(x) > get<0>(y);           // 按和最小堆
    }
};
vector<vector<int>> kSmallestPairs(vector<int>& a, vector<int>& b, int k) {
    int n = a.size(), m = b.size();
    priority_queue<tuple<int,int,int>, vector<tuple<int,int,int>>, Cmp> pq;
    for (int i = 0; i < min(n, k); i++)         // 每行只种流头
        pq.emplace(a[i] + b[0], i, 0);
    vector<vector<int>> res;
    while (!pq.empty() && (int)res.size() < k) {
        auto t = pq.top(); pq.pop();
        int i = get<1>(t), j = get<2>(t);
        res.push_back({a[i], b[j]});
        if (j + 1 < m) pq.emplace(a[i] + b[j + 1], i, j + 1);  // 行内顺延
    }
    return res;
}
```

## 解法三: 贪心剪枝（无堆版本思路）

### 思路
可再观察到:k 对候选都落在"前 k 行 × 前 k 列"内(`i<k` 或 `j<k` 的格子才可能进前 k)。可只把这一小块 `k×k` 排序取前 k;但通常仍需小顶堆或部分排序,不如解法二彻底。实际若 k 很小且数组很长,可对**逐列前缀**与堆选优组合处理,细节略。

### 复杂度
- 时间复杂度: O(k² log k)(k 很小时可用)
- 空间复杂度: O(k²)
