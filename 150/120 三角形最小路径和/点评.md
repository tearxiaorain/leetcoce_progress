# 120. 三角形最小路径和 — 代码点评

## 使用的方法
**自顶向下一维滚动 DP**。`arr` 存上一行的最小值，`brr` 算当前行，每行处理完 `swap`。最后对最后一行排序取最小值。

## 复杂度分析
- 时间复杂度: **O(n² + n log n)** — DP O(n²) + 最后 sort O(n log n)
- 空间复杂度: **O(n)** — 双数组

> ⚠️ `sort` 将 O(n²) 的 DP 拉到了 O(n² + n log n)，虽然 n log n 项可忽略，但完全没必要。

## 代码评价

### 优点
- DP 转移逻辑正确：`arr[j-1]`（左上）和 `arr[j]`（右上）取较小值加当前值
- 边界处理到位：`j==0` 时无左上方，`j==i` 时无右上方
- 与 63、64 题保持统一的双数组滚动风格

### 可改进之处
1. **`sort` 取最小值是大材小用**: `sort(arr, arr+n)` 是 O(n log n)，直接用 `*min_element(arr, arr+n)` 或遍历一遍即可 O(n)
2. **内存泄漏**: `new int[n]` 未 `delete[]`
3. **INT_MAX 初始化多余**: `l1 = INT_MAX; l2 = INT_MAX` 然后立即被覆盖
4. **手动 min 啰嗦**: 同 64 题问题，`if(l2<l1) brr[j]=l2` 不如 `brr[j] = min(l1, l2)`
5. **可用自底向上简化**: 从最后一行往上推，只需一个一维数组，代码更短且不需要最后取 min

### 代码风格
- 与其他 DP 题风格完全一致（双数组 + swap），已形成个人模板
- 冗余 include（stack、map、set）

## 总结
> 自顶向下 DP 正确，唯一的小问题是最后用 `sort` 取最小值浪费了 O(n log n)。改为 `min_element` 或直接改自底向上可一步到位。
