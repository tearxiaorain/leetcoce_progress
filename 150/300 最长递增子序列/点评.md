# 300. 最长递增子序列 - 代码点评

## 用户代码概览

```cpp
int lengthOfLIS(vector<int>& nums)
{
    int n=nums.size();
    int *arr=new int[n];
    int *len=new int[n];
    arr[0]=nums[0];
    len[0]=1;
    for(int i=1;i<n;i++)
    {
        int flag=0;
        int ind;
        int max=0;
        for(int j=i-1;j>=0;j--)
        {
            if(nums[i]>arr[j])
            {
                flag++;
                if(max<len[j])
                {
                    max=len[j];
                    ind=j;
                }
            }
        }
        if(!flag)
        {
            arr[i]=nums[i];
            len[i]=1;
        }
        else
        {
            arr[i]=nums[i];
            len[i]=len[ind]+1;
        }
    }
    int max_l=0;
    for(int i=0;i<n;i++)
    {
        if(max_l<len[i])
            max_l=len[i];
    }
    return max_l;
}
```

---

## 算法分析

代码实现了标准的 **O(n²) 动态规划** 解法：

- `len[i]`：以 `nums[i]` 结尾的最长递增子序列长度（即 DP 数组）
- `arr[i]`：始终赋值为 `nums[i]`，实际等同于 `nums[i]`
- 状态转移：`len[i] = 1 + max{ len[j] | j < i 且 nums[j] < nums[i] }`

**算法正确**，对于示例 `[1,3,6,7,9,4,10,5,6]` 能得到正确结果。

---

## 具体问题

### 1. 内存泄漏（严重）

```cpp
int *arr=new int[n];
int *len=new int[n];
```

使用 `new` 分配了动态数组，但函数结束时**没有 `delete[]`**，造成内存泄漏。LeetCode 的 OJ 环境每次调用后可能不会立即回收，多次调用会累积泄漏。

**修复：** 使用 `vector<int>` 替代原始指针：
```cpp
vector<int> len(n, 1);
```
或者在函数末尾添加 `delete[] arr; delete[] len;`。

### 2. `arr` 数组完全冗余

代码中 `arr[i]` 自始至终被赋值为 `nums[i]`，从未被修改为其他值。因此 `nums[i] > arr[j]` 等价于 `nums[i] > nums[j]`。`arr` 数组可以完全删掉，直接用 `nums`。

### 3. 变量 `ind` 未初始化

```cpp
int ind;           // 未初始化
int max=0;
for(...) {
    if(nums[i]>arr[j]) {
        if(max<len[j]) {
            max=len[j];
            ind=j;  // 这里才赋值
        }
    }
}
// ...
len[i]=len[ind]+1;  // 使用 ind
```

虽然逻辑上 `ind` 在 `flag>0` 时一定会被赋值（因为 `max=0 < len[j]≥1`），但编译器可能产生警告，且依赖这种隐式保证不够健壮。建议初始化为 `ind = -1` 或在使用前增加防御性检查。

### 4. 变量命名 `max` 与 `std::max` 冲突

由于代码中有 `using namespace std;`，局部变量 `max` 会遮蔽 `std::max` 模板函数。虽然此处没有直接使用 `std::max`，但这是个不良习惯，可能在某次修改时引入难以排查的编译错误。

### 5. `len` 数组可初始化为 1

DP 数组每个位置至少为 1（单个元素自身构成子序列），可以一步初始化：
```cpp
vector<int> len(n, 1);
```
这样可以省去 `if(!flag)` 分支中的 `len[i]=1`。

### 6. 效率：O(n²) 可在极端数据下超时

当 `n=10⁵` 时，O(n²) 会超时。面试中 O(n²) 可以作为起步，但建议提及 O(n log n) 的贪心+二分解法（耐心排序）。

### 7. `main` 函数中的无关代码

```cpp
int arr[9] = {1,3,6,7,9,4,10,5,6};
vector<int> n(0);
for (int i = 0; i < 9; i++) {
    n.push_back(arr[i]);
}
```

测试数据 `{1,3,6,7,9,4,10,5,6}` 适合验证，但无伤大雅。

## 优化后的参考代码

```cpp
int lengthOfLIS(vector<int>& nums) {
    int n = nums.size();
    vector<int> dp(n, 1);
    int ans = 1;
    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = max(dp[i], dp[j] + 1);
            }
        }
        ans = max(ans, dp[i]);
    }
    return ans;
}
```

## 总体评价

| 维度 | 评价 | 说明 |
|------|------|------|
| 算法正确性 | 正确 | DP 思路和状态转移正确 |
| 时间复杂度 | O(n²) | 基础解法，大数据会超时 |
| 空间复杂度 | O(n) | 使用了两个 n 大小的数组 |
| 代码规范 | 需改进 | 内存泄漏、未初始化变量、冗余数组 |
| 可读性 | 尚可 | 逻辑清晰但变量命名可优化 |

**核心建议：**
1. 优先修复内存泄漏，用 `vector` 替代原始指针
2. 删除冗余的 `arr` 数组
3. 初始化所有变量
4. 面试中建议在给出 O(n²) 解法后，主动提及 O(n log n) 的优化方向
