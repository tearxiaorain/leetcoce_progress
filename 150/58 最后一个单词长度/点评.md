# 58. 最后一个单词的长度 — 代码点评

## 使用的方法
**从右向左双阶段扫描**。第一阶段跳过末尾空格直到遇到非空格字符；第二阶段统计连续非空格字符数即为最后一个单词长度。

## 复杂度分析
- 时间复杂度: O(n)，最坏扫描整个字符串
- 空间复杂度: O(1)

## 代码评价
- 优点:
  1. 算法选择正确——从右向左扫描是最优解法（O(n) 时间，O(1) 空间）
  2. 两阶段扫描逻辑清晰
- 可改进之处:
  1. **潜在越界风险（严重）**: while 条件中 `s[n-1]` 在 `n > 0` 之前求值。当 n=0（空字符串）时，`s[-1]` 导致未定义行为。应交换条件顺序：`while (n > 0 && s[n-1] == ' ')`
  2. **冗余的 break 检查**: 循环体内的 `if (n <= 0) break;` 在正确放置 `n > 0` 条件后变得多余，可删除
  3. **n 递减后的边界**: 第一个 while 中 `n--` 后 n=0，下次循环检查 `s[-1]` 同样有风险，即使有 break 保护也是补丁式修复
  4. **main 函数残留**: `prises` 数组来自其他题目（买卖股票），与本题无关，应清理
  5. **未使用的 header**: `<vector>` `<algorithm>` 未在解题函数中使用
- 代码风格: 简洁，两段 while 对称；但边界处理不够健壮

## 总结
> 从右向左扫描的思路正确，但 while 条件中 `s[n-1]` 先于 `n>0` 求值存在越界隐患，交换条件顺序即可修复。
