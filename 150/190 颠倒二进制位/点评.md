# 190. 颠倒二进制位 — 代码点评

## 使用的方法
**逐位拆解 + 重新组装**：先用 `k % 2` 把入参的低 32 位依次取出来存进 `vector<int> flag(32)`（`k >>= 1` 逐位右移），再从 `i = 31` 到 `0` 反向组装，用 `k` 作为 2 的幂权重（`k <<= 1`）把为 1 的位累加回 `sum`。

## 复杂度分析
- 时间复杂度: O(32) = O(1)（固定两趟 32 次循环）
- 空间复杂度: O(32) = O(1)（`flag` 数组 32 个 int）

## 代码评价
- 优点:
  - **答案正确**：`k % 2` 即使 `k` 为负数也能取到当前位（-1 视作 1），所以输入以有符号整数给出时同样成立；32 位一轮不落，最高位与最低位互换
  - 固定 32 轮循环（没有写成 `while (n)`），保证高位为 0 的位也被搬到结果的低位，这一点很多写法会漏
  - 返回类型虽是 `int`，但按位结果与 `uint32_t` 一致（调用方做隐式转换后数值正确），边界值如 0、1、全 1 都不会错
- 可改进之处:
  - **不需要 `flag` 数组**：`res = (res << 1) | (n & 1); n >>= 1;` 一趟 32 次循环直接得到答案，省掉 32 个 int 和两趟遍历；`n` 声明成 `uint32_t` 后右移还是逻辑移位，语义最干净
  - **`k <<= 1` 存在未定义行为风险**：当 `k` 走到 2³¹ 再左移一位就进入有符号 `int` 的符号位，标准里是 UB（实测结果碰巧正确）；把 `sum / k` 改成 `uint32_t` 即可，或者干脆不用权重法
  - 重建那段可以用 `sum |= k` 之类的位运算替代 `if (flag[i]) sum += k;`，少一个分支
  - 想更进一步可用**分治掩码 5 步法**（相邻 1 位、2 位、4 位、8 位、最后高低 16 位交换），完全没有循环；若该函数要被调用很多次，还可以用 8 位查表法（见题解小结）
  - 建议把签名写成平台要求的 `uint32_t reverseBits(uint32_t n)`，避免依赖 `int ↔ uint32_t` 的隐式转换
- 代码风格: `flag / k / sum` 命名不达意（`k` 先后表示输入值、权重，语义漂移），建议 `bits / res / weight`

## 总结
> 32 位逐位拆解与组装逻辑正确，AC；用 `uint32_t` + 一趟 `res = (res << 1) | (n & 1)` 就能省掉整个 `flag` 数组并避开 `k <<= 1` 的有符号溢出风险，追求极致则用分治掩码 5 步法。
> AC ✓
