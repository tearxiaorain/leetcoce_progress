# 124. 二叉树中的最大路径和 — 代码点评

## 使用的方法
**两次递归枚举"路径最高点"**：`maxPath(v, outl, outr)` 求"从 v 向下延伸（必须含 v）的最大单臂和"，空子树用哨兵 `-2000` 表示；`midorder` 遍历每个节点，把它当作路径最高点，用 `m1 = maxPath(v)`（只走一条臂）和 `m2 = outl + outr + v->val`（左右两条臂都用上）去更新全局 `max`。

## 复杂度分析
- 时间复杂度: O(n²)（每个节点都要重新递归整棵子树；退化链最坏 O(n²)，平衡树约 O(n log n)）
- 空间复杂度: O(h)（两层递归栈，h 为树高）

## 代码评价
- 优点:
  - **思路成立**：每条路径的最高点唯一，遍历所有节点就能覆盖全部路径；单臂用 `m1`、双臂用 `m2`，两类都更新了答案
  - 三个候选值 `{val, l + val, r + val}` 用 `sort` 取最大，写法简短不易错
  - 全负数用例也不会出错：`max` 初值 `INT_MIN`，任何节点的 `arr[0] = val` 都会被计入
  - 入度为 0 的哨兵 `-2000` 在本题取值范围内恰好无害——真实单臂和一定 ≥ -1000（因为 `arr[0]` 始终参与取最大），带哨兵的 `m2` 又必然 ≤ `m1`
- 可改进之处:
  - **主要问题：O(n²) 可以降到 O(n)**。现在同一个子树会被反复递归，其实后序遍历里每层只需返回"本节点的单臂贡献"、同时用"左右贡献 + 本节点值"更新全局答案，一次遍历即可（见题解解法二）
  - **`-2000` 是魔法哨兵**：本题值域是 -1000 ~ 1000，单臂和的真实下限远低于 -2000，只是恰好不会成为最大值才没出错；换成 `INT_MIN` / `LLONG_MIN`，或者显式判 `if (!root) return 0;` 再按需裁剪负贡献，语义才稳
  - 变量名 `max` 遮蔽了 `std::max`（又 `using namespace std`），建议改 `best`
  - `sort(arr, arr + 3)` 比两次 `if` 比较更重也更难读，直接写 `max({a, b, c})` 或两个分支即可
  - `midorder` 这个名字与用途不符（它只是枚举节点，没有做中序处理），建议 `enumerateAll` 或 `checkAllNodes`
  - 出参 `outl / outr` + 返回值的组合偏绕：可以先 `int l = maxPath(left, ...)` 再统一用"全局 best + 返回值"的结构，减少一次数据搬运
  - 链状树深度可达 3×10⁴，递归栈有风险，必要时改显式栈后序；`#include <math.h>` 未使用
  - `main` 里把最有意思的用例都注释掉了（只留 1/2/3 的全正数树），而"全负数"和"经过根的两臂路径"才是这题的坑，建议补 `[-3]`、`[-2,-1]`、`[1,-2,-3]` 这类用例
- 代码风格: `arr[3] + sort` 是"取三者最大"的取巧写法，配合 `outl/outr` 出参让函数职责不够单一

## 总结
> 枚举最高点的思路正确、两类路径都覆盖到了，AC（因解题规模小、O(n²) 在本题约束下可过）；把两次递归合并成一次后序遍历（返回单臂贡献 + 更新全局答案）即为标准 O(n) 写法，同时建议去掉 `-2000` 魔法哨兵并给变量改名避开 `std::max`。
> AC ✓
