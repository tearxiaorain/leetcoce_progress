# 22. 括号生成 — 代码点评

## 使用的方法
**DFS 回溯 + 计数剪枝**：`fun(res, left, right, path)` 中 `left` 是"还剩几个左括号没放"，`right` 是"当前未闭合的左括号个数"。递归里只有两件事：`left > 0` 时放 `(`（`left--, right++`）；`right > 0` 时放 `)`（`right--`）；`left == 0 && right == 0` 时收答案。

## 复杂度分析
- 时间复杂度: O(Catalan(n) · n)（答案数为 C(2n,n)/(n+1)，每个答案由长度 n 的路径拼出；常数因每层整串拷贝而放大）
- 空间复杂度: O(n)（递归栈 + 路径串，不计结果集）

## 代码评价
- 优点:
  - **剪枝条件是准的**：只有 `right != 0` 才允许放右括号，等价于"任意前缀中右括号不多于左括号"，因此生成的串全部合法、互不重复，数量正好是 Catalan(n)（n = 8 时 1430 个）
  - 终止条件完整：必须 `left == 0 && right == 0` 才收答案，`left == 0` 但还有未闭合左括号时只能一路补右括号，不会漏解
  - `res / path` 用引用传递，结果集没有反复拷贝
- 可改进之处:
  - **`string t = path;` + `path = t;` 每层都整串拷贝**，是这份代码最大的常数开销；标准写法是 `path.push_back(ch)` 递归、回来 `path.pop_back()`，O(1) 回退
  - `int &left, int &right` 传引用 + 手工 `left--/left++` 复位，少写一行复位就会静默出错；建议改成**按值传计数**，语义取"已用左/右括号数"，判断写成 `left < n`、`right < left`，全部手工回滚都可以删掉
  - 分支不对称：`left == 0` 时"只能放右括号"写在 `else` 里，"二选一"写在另一个 `else` 里，两处逻辑其实可以统一成两段独立的 `if`
  - `main` 里还留着上一题（34 题）的数组构造与 `vector<int> a`，是死代码，建议清掉
- 代码风格: 函数名 `fun`、参数 `a` 信息量为零，建议改成 `backtrack` / `path` / `open` / `unmatched`

## 总结
> 回溯框架与剪枝条件都正确，结果数量与 Catalan 数一致，AC；把"整串拷贝 + 引用计数"换成"push_back/pop_back + 按值计数"，代码更短、更快、更不易写错。
> AC ✓
