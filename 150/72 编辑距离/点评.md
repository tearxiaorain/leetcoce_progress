# 72. 编辑距离 — 代码点评

## 使用的方法
**二维 DP（自底向上）**：`dp[i][j]` 表示 `word1` 前 `i` 个字符转成 `word2` 前 `j` 个字符的最少操作数，第 0 行填 `j`、第 0 列填 `i`，转移时把三种操作写成三项取最小——替换用 `dp[i-1][j-1] + (word1[i-1] != word2[j-1])` 的写法，把"末位相同则零代价"和"不同则替换"合并成了一行。

## 复杂度分析
- 时间复杂度: O(m·n)
- 空间复杂度: O(m·n)

## 代码评价
- 优点:
  - **递推与初始化都是标准解**：边界 `dp[i][0] = i`、`dp[0][j] = j` 正确，内层三项分别对应替换 / 插入 / 删除，`dp[m][n]` 即答案
  - `dp[i-1][j-1] + (word1[i-1] != word2[j-1])` 用布尔值当 0/1 代价，省掉一层 `if-else` 分支，是本题很地道的写法
  - 三值取最小用手工比较完成，不依赖 `min({...})` 的初始化列表重载，兼容性更好
  - 空串情形自然成立（`m == 0` 或 `n == 0` 时答案就是另一个串的长度）
- 可改进之处:
  - **函数里留着调试用的矩阵打印循环**：每次调用都会把整张 dp 表输出到 stdout，提交到平台会污染输出、也白白花掉 O(mn) 的 I/O，建议删除或注释掉（对照题解里的干净版本）
  - 注释里 **`d2` / `d3` 标反了**：`dp[i][j-1] + 1` 是"插入"（让 `word2` 少一位），`dp[i-1][j] + 1` 是"删除"（让 `word1` 少一位），现在标成删除/插入正好相反，容易误导后来复习的自己
  - `vector<int> t(n + 1, false);` 用 `false` 初始化 `int`，语义别扭（这行像是从 `bool` 版本改过来的），写 0 更清楚
  - 空间可以从 O(mn) 压到 O(n)：转移只依赖上一行和本行左邻，用一维数组 + 暂存左上角即可（见题解解法三）
  - 可选：若想省内存又保留递推，可先把较短的串作为列（`swap` 两个串不影响答案）
- 代码风格: 循环用 `i < m + 1` 而不是 `i <= m`，读起来稍绕；其余结构清晰

## 总结
> 标准二维 DP，初始化、转移、边界都对，AC；把调试打印删掉、注释里插删方向纠正过来，再用一维滚动数组替代二维表，就是一份可以直接背的模板。
> AC ✓
