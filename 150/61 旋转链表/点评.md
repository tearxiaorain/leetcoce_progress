# 61. 旋转链表 — 代码点评

## 使用的方法
**计数 + 成环剪断**：先数出长度 `n`（同时让尾节点停驻），把尾节点 `next` 接到 `head` 成环；然后 `r = k % n`，从 `head` 走 `r = n - r - 1` 步到达"新尾"（新头的前一个节点），令 `res = h->next` 作为新头并把 `h->next` 置空剪断返回。整倍数时 `k%n==0` → `r = n-1` 恰好走回原尾、剪在头尾之间，返回原链表，无需额外特判。

## 复杂度分析
- 时间复杂度: O(n)（数长度一遍 + 走断点至多 n 步）
- 空间复杂度: O(1)

## 代码评价
- 优点:
  - 成环后"走 `n-k-1` 步到新尾再剪"一步到位，O(n) O(1) 且原地不新建节点，思路干净
  - 已核实与平台 AC 版行为一致：官方两例 + 3000 组随机对拍 + k 为长度整数倍，全部通过
  - `k == 0` 提前返回 + 空链表返回 `nullptr`，边界有照顾
- 可改进之处:
  - **本地副本曾比 AC 版多一行 `r = n - r;`，使代数变成 `k%n - 1`（变成左旋、过不了例 1），已删掉对齐为 `n - r - 1`**——提示：成环步数必须一次算对，`r` 不能先被改写再二次取 `n - r`
  - 成环后若忘记在返回前剪断会留下环导致打印/遍历死循环，此题已正确剪断；可加一行注释说明"断点步数是 n-k-1 而非 n-k，因为要停在新区段前一个节点"
  - 命名 `r`（既当余数又当步数）略含混，建议拆成 `k %= n` 后直接 `int steps = n - k - 1;` 表达更清晰
- 代码风格: 紧凑、逻辑正确，无明显冗余

## 总结
> 成环 + 走 `n-k-1` 步剪断，O(n) O(1)，验证全过；唯一风险点是断点步数公式，已与平台 AC 版对齐。
