# 112. 路径总和 — 代码点评
## 使用的方法
递归 DFS（减法思想）。从根向下递归，每层用 `targetSum - root->val` 得到剩余和，到达叶子节点时判断剩余和是否等于当前节点值。

## 复杂度分析
- 时间复杂度：O(n)，最坏情况需要遍历所有节点。
- 空间复杂度：O(h)，递归栈深度为树高，最坏（链状树）为 O(n)。

## 代码评价

**优点**：
- 标准减法递归，逻辑正确，叶子处判断 `targetSum == root->val` 即"剩余和恰好减到 0"。
- 用 `if(root->left)`、`if(root->right)` 守卫，避免对空指针做无意义的递归调用。
- 首部 `if(!root) return false;` 处理空树边界，正确。

**可改进**：
- 第 43-44 行 `int b1,b2; b1=b2=false;` 类型应改为 `bool`，用 `false` 给 `int` 赋值虽能隐式转换但语义不清。
- 第 38-42 行的叶子判断可以合并为 `return targetSum == root->val;`，避免 if-else 冗余。
- 由于首部已处理空节点，第 45-48 行的左右分支可以简化为一行：`return hasPathSum(root->left, targetSum - root->val) || hasPathSum(root->right, targetSum - root->val);`（空节点会在下一层被首部 `if(!root)` 拦截）。
- 头文件包含了一些未使用的 `<vector>`、`<stack>`、`<queue>`、`<map>`、`<set>`、`<string>`、`<unordered_map>`、`<algorithm>`（实际用到 `<iostream>`）。

**风格**：
- 代码结构清晰，递归思路标准。
- 变量名 `b1`/`b2` 建议改为 `leftHas`/`rightHas` 等更具语义的名称。

## 总结
> AC ✓

代码正确实现了路径总和的判断，采用减法递归，复杂度 O(n)/O(h)，是合格的标准解法。存在一些可精简之处（bool 类型、合并叶子判断、简化为一行递归），但不影响正确性。
