# 2. 两数相加 — 代码点评

## 使用的方法
**原地修改 + 进位前传**。先找到较长链表确保 l1 为长链，然后直接在 l1 上累加 l2 的值，进位不存变量而是直接加到 `l1->next->val` 上，最后单独遍历处理链式进位。

## 复杂度分析
- 时间复杂度: **O(max(m, n))** — 三趟遍历（找长链 + 逐位相加 + 进位传播），均为 O(n)
- 空间复杂度: **O(1)** — 原地修改，仅在进位溢出末尾时 new 节点

## 代码评价

### 优点
- **原地修改节省空间**：不创建新链表，直接在 l1 上操作，空间 O(1)
- **进位前传思路巧妙**：把进位直接加到 `l1->next->val`，省去了 `carry` 变量的维护
- **三趟遍历结构清晰**：找长链 → 相加 → 进位传播，每步职责单一
- 处理了 l2 比 l1 长的情况（swap 确保 l1 总是更长）

### 可改进之处
1. **三趟遍历可合并为一趟**：标准解法用 dummy 节点一趟同时处理两个链表，代码更紧凑
2. **修改了输入链表**：函数调用后 l1 被破坏，调用方不能再使用原链表
3. **`if(h1) ;` 空语句**：第 47-48 行的空 `if` 分支是无用代码，应删除或用 `if(!h1 && h2) swap(l1,l2)` 简化
4. **冗余 include**：`stack`、`map`、`set` 等头文件未使用

### 代码风格
- 变量命名简洁（`h1`, `h2`, `c`），其中 `c` 未使用（死变量）
- 缩进风格一致
- `add` 方法中 `while` 的缩进缺失了花括号（单行省略），风格不统一

## 总结
> 原地修改方案思路独特，进位前传避免了 carry 变量，三趟遍历每步清晰。小瑕疵是空 if 分支和未使用变量。整体正确可用。
