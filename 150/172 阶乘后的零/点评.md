# 172. 阶乘后的零 - 代码点评

## 用户代码概览

代码中包含了两个版本的实现：

---

## 版本一：`trailingZeroes1`（模拟乘法求尾零）

```cpp
int trailingZeroes1(int n) {
    int a=n;
    int count=0;
    for(int i=n-1;i>0;i--)
    {
        int r1=a%10;
        while(a&&!r1) { count++; a/=10; r1=a%10; }
        int t=i;
        int r2=t%10;
        while(t&&!r2) { count++; t/=10; r2=t%10; }
        int r=(r1*r2)%10;
        int m=r1*r2;
        while(m&&!r) { count++; m/=10; r=m%10; }
        a=m;
    }
    int rr=a%10;
    while(a&&!rr) { count++; a/=10; rr=a%10; }
    return count;
}
```

### 问题分析

**致命缺陷：只保留最后一位数字无法正确计算尾随零数量。**

该方法试图通过只保留每次乘法结果的最后一位非零数字来模拟阶乘计算。例如，当 `a=12`（末尾数字 2）乘以 `i=15`（末尾数字 5）时，`r1*r2 = 10`，代码会认为产生了一个零。但实际上 12 × 15 = 180，确实产生了一个零——看起来似乎可行。

然而反例很多：`a = 25`（末尾 5）乘以 `i = 4`（末尾 4），`5 * 4 = 20`，代码只取了 `(5*4)%10 = 0`，然后试图剥离尾零得到 2。但 `25 × 4 = 100`（两个尾零），只剥离一个零得到 10，最后一位仍是 0，这与代码的假设矛盾——代码假设剥离尾零后得到的是非零数字 `a = m`（但 m=10，不是一位数）。

**根本原因：** 乘法中尾随零的数量不由最后一位数字的乘积决定，而是由参与运算的完整数字的因子 2 和 5 决定。例如：
- `25 × 4 = 100`，尾随零来自 25 中的两个 5 和 4 中的两个 2
- 仅看最后一位（5 和 4）无法得知有两个零

**其他问题：**
- 逻辑极其复杂、难以阅读和维护
- 变量命名不清晰（`r1`, `r2`, `a`, `m`）
- 多个嵌套 while 循环使控制流混乱

### 评分：不可用 / 不推荐

## 版本二：`trailingZeroes`（统计因子 2 和 5）

```cpp
int trailingZeroes(int n) {
    int num_2,num_5,count;
    num_2=num_5=count=0;
    for(int i=1;i<=n;i++)
    {
        int t=i;
        while(t%5==0) { num_5++; t/=5; }
        while(t%2==0) { num_2++; t/=2; }
    }
    count=num_2;
    if(num_5<num_2) count=num_5;
    return count;
}
```

### 优点

- **算法正确**：抓住了核心——尾随零由因子 2 和 5 的数量决定，取 min(num_2, num_5)
- 思路比版本一清晰很多，从数学本质上解决问题

### 可改进之处

| 问题 | 说明 | 建议 |
|------|------|------|
| 时间复杂度 O(n log n) | 对每个数 1..n 都做因子分解 | 用 n/5 + n/25 + ... 可做到 O(log n) |
| 统计因子 2 是多余的 | n! 中因子 2 永远 >= 因子 5 | 只需统计因子 5，直接返回 num_5 |
| 变量未初始化 | `count` 虽然后面被赋值，但声明时未初始化不是好习惯 | 声明即初始化 |
| `using namespace std;` | 在大型项目中可能引发命名冲突 | 建议用 `std::` 前缀 |
| main 中无关代码 | `vector<int> n` 和数组 arr 的填充与本函数无关 | 清理无关代码 |

### 修改建议

```cpp
int trailingZeroes(int n) {
    int count = 0;
    while (n >= 5) {
        n /= 5;
        count += n;
    }
    return count;
}
```

## 总体评价

| 维度 | 版本一 | 版本二 |
|------|--------|--------|
| 正确性 | 错误 | 正确 |
| 效率 | O(n²) 级别 | O(n log n) |
| 可读性 | 极差 | 尚可 |
| 数学洞察 | 缺失 | 抓住了核心 |

**进步方向明确**：从版本一到版本二已经是从"暴力模拟"到"数学思维"的跃迁，但还可以进一步从 O(n log n) 优化到 O(log n)，并去掉冗余的因子 2 统计。

**核心经验**：处理阶乘/质因数相关问题时，优先寻找数学规律而非模拟计算过程。
