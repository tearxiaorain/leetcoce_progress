# 155. 最小栈 — 代码点评

## 使用的方法
使用 vector 作为底层存储，用 `count` 追踪栈大小，用 `min` 和 `ind` 变量试图缓存最小值和其位置，并在缓存失效时回退到 O(n) 扫描。

## 复杂度分析
- 时间复杂度: push O(1)（均摊），pop O(1)，top O(1)；**getMin 最坏 O(n)**（当 ind 为 -1 时遍历所有元素重新找最小值）
- 空间复杂度: O(n)，vector 存储元素

## 代码评价
- 优点: 尝试用两个变量（min 和 ind）缓存最小值以避免每次都遍历，思路方向正确；`top()` 和 `pop()` 的基本逻辑没有问题。
- 可改进之处:
  1. **push 的 bug**: `if(min > value && ind != -1)` ——初始状态 `ind = -1`，意味着第一个 push 永远不会更新 `min`。当首次调用 `getMin()` 时 `ind == -1` 触发扫描，但这导致第二个 push 后的 min 比较也依赖 ind != -1 的判断，整体逻辑脆弱。
  2. **pop 不完整**: 仅在 `ind >= count` 时重置 min/ind，但当栈中删除了最小元素后、其他元素仍包含之前的最小值候选时，无法正确反映新的最小值。应该用辅助栈或存差值的方式保证 O(1) getMin。
  3. **getMin 不是 O(1)**: 题目要求所有操作都在 O(1) 时间内完成，当前实现在 ind 失效时退化为 O(n) 扫描，不满足题目要求。
  4. `size` 变量混乱：初始声明 `int size = st.size()` 在成员声明阶段执行（此时 st 为空），而后又在构造函数中重新赋值，且 push 时手动维护，完全可以用 `st.size()` 替代。
  5. 未使用 vector 的 `push_back`/`pop_back` 原生能力，而是用 `count` 手动维护，增加了复杂度和出错可能。
- 代码风格: 包含多个未使用头文件（`<map>`, `<set>`, `<string>`），main 测试代码中有内存泄漏（new 后未 delete）。

## 总结
> 基本栈操作正确，但 getMin 不满足 O(1) 要求，且 push 中 min 更新的条件判断有缺陷。应使用辅助栈或差值法实现真正的 O(1) 最小栈。
> AC ✓（但 getMin 非 O(1)）
