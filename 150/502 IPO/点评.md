# 502. IPO — 代码点评

## 使用的方法
**双堆贪心**：把全部项目按 `cost` 塞进最小堆 `pqc`（成本优先），再用最大堆 `pqp`（利润优先）收"已解锁"项目。每轮 `while` 把 `pqc` 中所有 `cost <= w` 的项目转进 `pqp`，然后取 `pqp` 堆顶（当前可做项目中利润最大者）执行、`w += 利润`；`pqp` 为空则无法再启动，提前退出。

## 复杂度分析
- 时间复杂度: O((n + k) log n)（每个项目最多进出堆一次 + k 次取顶）
- 空间复杂度: O(n)

## 代码评价
- 优点:
  - **方法正确且干净**：贪心 + 双堆正中本题标准解法；用"成本最小堆"代替先排序数组，每个项目解锁一次、只进不出，天然单调，无需重复扫描
  - 边界处理到位：`pqp.empty()` 提前 break，避免资金不足时空转；`w` 只增不减符合题意
  - `val_cost` 封装 (利润, 成本)，`cmp1/cmp2` 比较器语义清晰
- 可改进之处:
  - **`val_cost` 同时装"成本比较键"和"利润比较键"，两个堆各存一份全量副本的引用**：当前每个项目在 `pqc` 和 `pqp` 里各存一个 `val_cost` 值对象（pqc 里的最终全部转给 pqp，内存峰值接近 2×n 份对象）。其实成本侧只需"按成本排队解锁"，可像题解那样按 `capital` **排序一个数组 + 单指针扫描**，只用一个利润堆，省一半堆节点（代码也更短）
  - `cmp` 两处布尔与 STL 期望相反容易写反（`return a.cost > b.cost` 才是最小堆），可加一行注释说明"成本小者优先"，避免日后改错
  - 可选：成本堆中元素仅在需要时出堆，属性上接近"待解锁优先队列"，与排序指针法二者皆可，当前实现是正确的
- 代码风格: 结构清楚，命名达意

## 总结
> 双堆贪心思路与实现都正确、O((n+k) log n) AC；可优化为"成本排序数组 + 单指针扫描 + 单一利润堆"，内存从两套堆降到一套、代码更短。
> AC ✓
