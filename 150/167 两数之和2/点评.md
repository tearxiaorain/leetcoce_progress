# 167. 两数之和2 — 代码点评

## 使用的方法
使用 map 存储"互补值→下标"映射，遍历数组时检查当前元素是否已被之前的互补值记录，若匹配则返回结果。本质上与 LeetCode 1（无序两数之和）相同的哈希表思路。

## 复杂度分析
- 时间复杂度: O(n log n)，`map`（红黑树）的 find/insert 均为 O(log n)
- 空间复杂度: O(n)，map 存储互补值

## 代码评价
- 优点: 思路正确——通过互补值映射在一次遍历中找到目标数对；`break` 及时退出循环；返回下标按要求从 1 开始（+1）。
- 可改进之处:
  1. **未利用数组有序性**: 题目明确数组是升序的，最优解法是用双指针（O(n) 时间 + O(1) 空间），而非哈希表。当前解法的空间复杂度为 O(n)。
  2. **使用了 map 而非 unordered_map**: map 的每次操作是 O(log n)，导致总时间复杂度 O(n log n)。若坚持哈希表解法，应使用 `unordered_map` 实现 O(n) 平均时间。
  3. `vector<int> res(0)` 写法可改为 `vector<int> res`，功能相同但更清晰。
  4. `flag` 变量递增后未被使用，属于冗余代码。
  5. 测试用例 `{100,4,200,1,3,2}` 并非有序数组，不能正确测试本题（虽然代码逻辑仍能跑通）。
  6. main 函数中包含无关的字母异位词测试数据。
- 代码风格: 基本规范，但有未使用的头文件（`<stack>`），可适当清理。

## 总结
> 哈希表解法能通过但不够优——题目强调了有序数组，应用双指针实现 O(n) 时间 + O(1) 空间的最优解。
> AC ✓（但未达最优）
