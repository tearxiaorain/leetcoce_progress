# 50. Pow(x, n) — 代码点评

## 使用的方法
**混合法：特殊情况硬编码 + 不完全的快速幂**。先处理大量特殊情况（x=0/1/-1, n=0/1/-1/2/-2），然后用 `long long` 处理负指数，主循环先快速平方到最大 2 的幂，再用循环补齐剩余次数。

## 复杂度分析
- 时间复杂度: **O(log n + k)**，k = n - 2^{floor(log₂ n)}。当 n 接近 2 的幂时 k 很小，但最坏情况 k ≈ n/2（如 n = 2³⁰ + 1），算法退化为 O(n)，会超时
- 空间复杂度: **O(1)**

## 代码评价

### 优点
- 特殊边界大量覆盖：x=0/1/-1 等极端情况都处理了
- 负数指数处理正确，用 `long long` 避免 INT_MIN 取反溢出
- 有快速幂的思想萌芽（`res*=res` 平方）

### 可改进之处
1. **算法不完全，最坏 O(n)**: 当前先跳到最大 2 的幂，再用线性循环补齐。当 n 较大且离 2 的幂较远时性能极差。例如 n=1073741825 (2³⁰+1)，第一轮跳到 2³⁰，剩余约 10 亿次线性乘法。应改用标准二进制快速幂（逐位处理，保证 O(log n)）
2. **特殊情况冗余**: x=1/-1 已经正确，但 n=1/-1/2/-2 这些情况并非必需，标准快速幂本身就能处理
3. **`count` 未初始化时从 0 开始**: 当 n=0 或 n=1 时已被前几条特殊 if 拦截，不会走到主循环。但 n=3 时循环正确，n=2 被拦截。逻辑上能跑通但不优雅
4. **可用 `n & 1` 判断奇偶**: 比 `n % 2` 位运算更快（虽然编译器通常能优化）

### 代码风格
- 前置特殊情况虽多但意图清晰
- `flag` 命名建议改为 `isNegative`
- 注释掉的暴力循环应删除

## 标准二进制快速幂参考
```cpp
double myPow(double x, int n) {
    long long N = n;
    if (N < 0) { x = 1.0 / x; N = -N; }
    double res = 1.0;
    while (N) {
        if (N & 1) res *= x;
        x *= x;
        N >>= 1;
    }
    return res;
}
```

## 总结
> 快速幂思想有但实现不完整，最坏 O(n) 会超时。特殊情况处理充分，整体逻辑正确但对大 n 性能不足。建议改用标准迭代快速幂。
