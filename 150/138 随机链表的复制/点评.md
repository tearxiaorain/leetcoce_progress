# 138. 随机链表的复制 — 代码点评

## 使用的方法
**双哈希表 + 下标中转**：第一遍建新链时用 `n_index`（原节点→序号）和 `index_n`（序号→新节点）两张表，把每个新副本挂到序号上（并预置 `nullptr ↔ -1` 的映射）；第二遍遍历原链，对每个节点的 `random` 先查它对应的序号，再查该序号对应的新节点，从而完成 random 的对接。

## 复杂度分析
- 时间复杂度: O(n)（两遍线性遍历 + 每步 O(1) 哈希查询）
- 空间复杂度: O(n)（两张哈希表，各 n 个条目；`index_n` 还额外保存了全部新建节点）

## 代码评价
- 优点:
  - **思路自洽、逻辑完整**：用「节点→序号」再「序号→新节点」的两段翻译处理 random，规避了「指针不能直接做下标」的问题；`nullptr` 也单独映射到 `-1`，random 为空时不会漏
  - 复杂度达标 O(n) O(n)，测试样例与官方案例一致
- 可改进之处:
  - **两张表冗余**：一张 `unordered_map<Node*, Node*>`（原节点→新节点）即可完成同样工作，`n_index` 与 `index_n` 属多余中转，浪费内存也增加出错面。map 直接用指针当 key，C++ 对指针的哈希天然支持
  - 多维护了一个「序号」维度后，第二遍还要做两次 find，代码偏绕；node→node 单表版两遍循环各 3 行就够
  - 可进一步做到 **O(1) 空间**（题解解法二）：原节点后内插副本 → 按 `cur->random->next` 连 random → 拆链还原，连哈希表都省掉
- 代码风格: 变量命名（`index_n/n_index`）含义清楚，但整体比标准单表版复杂

## 总结
> 双表下标法实现正确（样例可跑通），O(n) O(n) 达标；建议收敛为 `原节点→新节点` 单哈希表版，进阶可改「内插副本+拆链」做到 O(1) 额外空间。
