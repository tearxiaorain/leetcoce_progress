# 19. 删除链表的倒数第 N 个节点 — 代码点评

## 使用的方法
**哈希表记录位置**：用哑节点 `res` 兜底，从头到尾走一遍，把「位置下标 → 节点指针」存入 `unordered_map<int, ListNode*>`；由于下标从 0 计起，末节点位置恰为链表长度 `cnt`，倒数第 n 个的前驱就是位置 `cnt - n`，找到后直接 `it->second->next = it->second->next->next` 摘除。

## 复杂度分析
- 时间复杂度: O(n)（一次完整遍历 + O(1) 哈希查找）
- 空间复杂度: O(n)（一张存了 n+1 个节点的哈希表）

## 代码评价
- 优点:
  - **思路直白、正确性稳**：用「下标=长度」做倒数↔正数的换算很清晰，哑节点让删头节点也无需特判；逻辑一步到位
  - 删除直接用 `m[k]` 找到前驱节点修改 `next`，不会出现「被删节点无前驱」的情况
- 可改进之处:
  - **O(n) 空间非必要**：本题标准做法只需 O(1) 空间——两次遍历先数长度（或一次遍历的快慢指针），完全不需要把每个节点都存进 map。大 n 下哈希表还有扩容、内存开销
  - 现有实现**原地没有真正释放被删节点**（只是跳过），与 LeetCode 环境无关但作为工程实践可注意
  - 可改双指针一次遍历：`fast` 先走 n 步，`slow` 从哑节点出发，`fast` 到 null 时 `slow` 恰在待删前驱（见题解解法二），时间仍是 O(n) 但空间降到 O(1)
- 代码风格: 简洁，无多余分支

## 总结
> 哈希表存下标法 AC，O(n) O(n)；空间浪费在 map 上，建议改为「数长度两次遍历」或「快慢指针一次遍历」，空间降到 O(1)。
