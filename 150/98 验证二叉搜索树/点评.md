# 98. 验证二叉搜索树 — 代码点评
## 使用的方法
中序遍历 + 数组检查严格递增。用辅助函数 `preorder`（实际是中序遍历：先左、再根、后右）把整棵树的值收集到 `vector<int> arr`，再遍历 `arr` 判断是否满足 `arr[i-1] < arr[i]`（严格递增）。本质是利用"BST 中序遍历序列严格递增"这一性质。

## 复杂度分析
- 时间复杂度：O(n)，中序遍历访问每个节点一次，再扫描一遍数组，总计 O(n)。
- 空间复杂度：O(n)，`arr` 保存全部 n 个节点值，递归栈深度为树高 O(h)，综合为 O(n)。

## 代码评价

**优点**：
- 思路正确，利用 BST 中序遍历递增的经典性质，逻辑清晰易验证。
- 边界情况处理正确：空树 / 单节点时 `for` 循环不执行，`b` 保持初始 `true`，符合"空树和单节点是合法 BST"。

**可改进**：
- 函数名 `preorder`（第 34 行）与实际逻辑不符——它做的是**中序遍历**（左-根-右），命名极具误导性，应改名 `inorder`。
- 需要 O(n) 的 `arr` 额外空间。可改为只维护一个前驱值 `prev`，边中序遍历边比较 `当前值 > prev`，空间降为 O(h)（只需递归栈）。
- 第 45-54 行 `bool b = true; ... b = arr[i-1] < arr[i]; if(!b) break;` 写法绕，等价于 `for(...) if (arr[i-1] >= arr[i]) return false; return true;`，后者更简洁。
- `main` 中注释（第 59 行 `5,4,6,null,null,3,7`）与实际构造的树（第 63-67 行，即 `5,1,4,null,null,3,6`）不一致，建议统一；实际构造的 `[5,1,4,null,null,3,6]` 正是标准反例，能正确测出 false。
- 头文件包含了未使用的 `<stack>`、`<map>`、`<set>`、`<string>`、`<unordered_map>`、`<algorithm>`（实际用到 `<iostream>`、`<vector>`）。

**风格**：
- 符合 ACM 风格，`using namespace std;`。
- 变量名 `b` 含义模糊，建议 `valid` 等。

## 总结
> AC ✓

代码正确实现了 BST 判定，采用"中序遍历 + 递增检查"思路无误，复杂度 O(n)/O(n)。主要问题在于函数命名与实际遍历方式不符、以及用数组存储带来 O(n) 额外空间，可改为"维护前驱值一次遍历"降到 O(h)。
