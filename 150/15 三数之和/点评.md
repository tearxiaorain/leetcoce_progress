# 15. 三数之和 — 代码点评

## 使用的方法

用户实现了两种方法：

**方法1 (threeSum1)**: 使用 `map<int, vector<int>>` 存储所有二元组的和及其元素。对每个新元素 `nums[i]`，在 map 中查找 `-nums[i]`（即存在一对元素与当前元素之和为 0）。用 `map<vector<int>, int>` 做三元组去重。

**方法2 (threeSum, 主函数调用)**: 先用三层 `unordered_map` 去重（保留每个值最多 3 个副本），再对去重后的数组做双重循环 + `unordered_map` 补数查找。同样用 `map<vector<int>, int>` 对结果去重，找到三元组后 `sort` 保证顺序一致。

## 复杂度分析

**threeSum1**:
- 时间复杂度: **O(n² log n)** — 枚举所有 O(n²) 个二元组，每次 `std::map::find` / `insert` 操作 O(log(n²)) = O(log n)
- 空间复杂度: **O(n²)** — map `m` 存储最多 O(n²) 个二元组的和与元素值

**threeSum**:
- 时间复杂度: **O(n²)** — 去重阶段 O(n)，双重循环 O(n²)（内层 `unordered_map` 查找 O(1) 平均）；三元组去重 map 操作 O(log k)，k 为找到的三元组数
- 空间复杂度: **O(n + k)** — 去重用的 `unordered_map` + `rnums` O(n)，结果去重 map `r` O(k)，其中 k 为唯一三元组数量

> 最优解法（排序 + 双指针）: O(n²) 时间、O(1) 空间。用户解法时间上接近最优，但空间额外使用了 O(n)~O(n²)。

## 代码评价

### 优点
- 核心思路正确：将三数之和转化为"固定一个 + 两数之和"，符合经典解题框架
- `threeSum` 的前置去重（每值最多 3 副本）能有效缩减数据规模，减少重复三元组的产生
- 使用 `unordered_map` 进行补数查找，相比暴力 O(n³) 大幅优化
- `main` 中有测试代码，思路验证意识好

### 可改进之处
1. **排序 + 双指针优于哈希法**: 三数之和的最优解通过排序后用双指针，无需额外去重 map，空间 O(1)，且去重逻辑自然内嵌于指针跳过
2. **`map<vector<int>, int>` 去重代价大**: 用 `std::map` 存储三元组做去重，每个三元组插入 O(log k)；建议改用排序+双指针后天然去重
3. **`threeSum1` 空间 O(n²) 过大**: 存储所有二元组和与元素，当 n 较大时内存压力大，且 `map<int, vector<int>>` 的 vector 不断增长也有拷贝开销
4. **`count` 变量未使用**: `threeSum` 中 `count` 自增但从未被读取，属于死代码
5. **`main` 测试不完整**: `arr` 声明为 `int arr[9]` 但只 push 了 4 个元素（i<4），且未验证返回结果的正确性
6. **`threeSum1` 被注释的 sort 代码**: 对 res 中每个三元组排序的代码被注释掉但保留，应清理

### 代码风格
- 变量名偏简（`m`, `r`, `t`, `um` 等），在局部作用域可接受，但建议使用更描述性的名称
- `um1/um2/um3` 的重复模式可用一个循环或 `unordered_map<int, int>` 计数替代
- `using namespace std` 在工程代码中不推荐

## 总结
> 思路正确（两数之和扩展），但实现方式过于复杂。排序+双指针法更简洁高效，无需额外去重结构。当前代码有冗余逻辑和死代码，建议重构为标准的排序+双指针解法。
