# 49. 字母异位词分组 — 代码点评

## 使用的方法
**字符频次向量 + map 分组**。对每个单词统计 26 个字母的出现次数，得到 `vector<int>(26)` 作为该单词的"签名"，然后用 `map<vector<int>, int>` 将相同签名的单词映射到同一组编号，最后按组编号收集结果。

属于"字符计数作为键"的变体，直接用 vector 作键省去了拼接字符串的开销。

## 复杂度分析
- 时间复杂度: O(n * k + n * 26 * log g)，n 为单词数，k 为单词平均长度，g 为分组数。其中 n*k 来自字符统计，n*26*log g 来自 map 查找（每次键比较 O(26)）
- 空间复杂度: O(n * 26) = O(n)，存储所有频次向量

## 代码评价
- 优点:
  1. 用 `vector<int>` 作为 map 键是合理选择，避免了排序或字符串拼接
  2. 两阶段处理（先编号分组，再收集）逻辑清晰
  3. 正确选择了 `map` 而非 `unordered_map`（vector<int> 默认无 hash 特化）
- 可改进之处:
  1. **`map` 可用 `unordered_map` 替代**: 自定义一个 hash 函数对 `vector<int>` 做哈希，可将查找从 O(log g) 优化为 O(1)（实际收益不大，因为 g 通常很小）
  2. **`vector<int> a(num,0)` 存在冗余**: 可直接用 map 的 value 存 `vector<string>`，减少二次遍历；当前做法多了一次遍历但逻辑更清晰，各有利弊
  3. **可以边统计边分组**: 不需要新建 `arr` 存储所有频次向量，直接在循环中查询/插入 map，节省 O(n*26) 空间
  4. **未使用的 header**: `<stack>` 可删除；`<set>` 未直接使用
- 代码风格: 结构清晰，缩进一致，变量命名可更语义化（如 `a` → `groupIds`, `arr` → `signatures`）

## 总结
> 用频次向量作签名的分组方法正确高效，两阶段收集逻辑清晰；可优化为单次遍历节省空间。
