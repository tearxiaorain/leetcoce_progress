# 222. 完全二叉树的节点个数 — 代码点评

## 使用的方法
文件里有三个版本，`main` 用的是 `countNodes`（**二分 + 二进制路径定位**，满足进阶要求）：
1. 沿最左链求出层数 `h`（根为第 1 层）；
2. 完全二叉树最后一行的节点编号落在 `[2^(h-1), 2^h - 1]` 这个连续区间内，于是**对编号二分**；
3. `check(root, k)` 把编号 `k` 转成二进制串（`tobit`），去掉最高位后按位从根走（1 向右、0 向左），能走通说明该编号的节点存在——由于最后一行是从左往右填满的，"存在性"单调，二分成立。

另外 `countNodes2` 是不利用性质的朴素递归 O(n) 版本，`countNodes1` 是"有右子就向右、否则向左"的另一种走法。

## 复杂度分析
- 时间复杂度: O(log²n)（二分 O(log n) 次 × 每次 `check` 走 O(log n) 层）
- 空间复杂度: O(log n)（编号的二进制串；其余为常数）

## 代码评价
- 优点:
  - **做对了进阶要求**：没有退化成 O(n) 遍历，而是用"最后一行节点编号连续 + 存在性单调"来二分，这正是本题的标准套路之一
  - `check` 用"从根按二进制位左右走"来定位第 k 个节点，思路正确；`k = 1`（只有根）时循环不执行、直接返回 true，也不会漏
  - `h` 的求法与 `low = 2^(h-1)`、`high = 2^h - 1` 的上下界推导正确，单节点树（h = 1、区间 [1,1]）也能得到答案
  - 保留了一个 O(n) 的朴素版本作对照，方便验证
- 可改进之处:
  - **循环后那段收尾很险**：`if (check(root, mid)) return mid; else return mid - 1;` 依赖"最后一次 `mid` 只可能是答案或答案 + 1"这个隐含事实（二分结束时 `low = 答案 + 1`、`high = 答案`，确实如此，但读者要自己推）。直接 `return high;`（或 `return low - 1;`）即可，语义一目了然，也省掉一次可能重复的 `check`
  - **文件里 `countNodes1` 的走法其实更优**：完全二叉树最后一个节点的堆编号就等于节点总数，"能向右就向右、否则向左"走到最深最右的那个节点只需 O(h)，把路径当二进制数读出来就是答案——比正在使用的 O(log²n) 还快一档，可惜没被调用。建议补注释说明它的用途，并在 `main` 里跑一跑做交叉验证
  - `pow(2, h)` 走的是浮点、再隐式转 int，建议直接 `1 << h`（`h` 最大也就 16 左右，位移更干净也不会引入浮点误差）
  - `check` 每轮二分都新建一个字符串：`tobit` 里还用了 `s = "1" + s` 的**前插拼接**（O(L²) 常数）。可以直接用位运算边走边判：`for (int i = h - 2; i >= 0; i--) 走 (k >> i) & 1`，不用字符串
  - `countNodes` 开头那句 `string s = "";` 从未使用，可以删掉
  - `countNodes2` 是 O(n) 对照实现，留着无妨，但三个同名不同后缀的函数容易看混，建议用注释标清"朴素版 / 二分解 / 最右路径版"
  - `#include <math.h>` 建议改成 `<cmath>`（C++ 头文件）
- 代码风格: `tobit` 命名口语化（`toBinary`），`check` 建议改名 `nodeExists`，让"在判断第 k 个节点是否存在"的意图直接读出来

## 总结
> 二分行号 + 二进制路径定位的思路正确、O(log²n) 达到了题目进阶要求，AC；建议把收尾改成 `return high;` 以去掉对"最后一次 mid"的隐含依赖，并把 `pow(2, h)` 换成 `1 << h`；顺带一提，同文件里那个没被使用的 `countNodes1`（走最右路径读二进制）其实是 O(log n) 的更优写法。
> AC ✓
