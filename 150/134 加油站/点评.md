# 134. 加油站 — 代码点评

## 测试数据

`gas = [3, 1, 1]`, `cost = [1, 2, 2]`（main 中 push 了前 3 个元素）

期望输出：`0`（从 0 号站出发可行）

## 代码分析

### 算法思路

用户的核心逻辑：从 0 号站出发，用 `t` 跟踪当前油箱，用 `count` 跟踪总剩余油量。若 `t < 0`，则将起点重置为 `i+1` 并清零 `t`。最后根据 `count >= 0` 判断是否有解。

思路接近标准贪心，但实现存在几处偏差。

### 代码问题

**1. `t` 初始值不合理**

```cpp
int t = gas[0];   // 循环前已预加 0 号站油量
for (int i = 0; i < n; i++) {
    t -= cost[i % n];          // 先扣油
    // ...
    t += gas[(i + 1) % n];     // 再加下一站油
}
```

导致第一次迭代时：先消耗 `cost[0]` 再补充 `gas[1]`。这是一种"先消耗后补充"的错位逻辑——`t` 表示的是"到达 i+1 站并加满油后的状态"，而非标准做法中"到达 i 站加满油后再消耗"的顺序。虽然数学上等价（最终累加量相同），但语义上极易混淆。

**2. 变量命名差**

- `t` → 应为 `curTank` 或 `tank`
- `ind` → 应为 `start`
- `count` → 应为 `totalSurplus`
- `fun` → 函数名无意义，应删除或改为 `simulate`

**3. 冗余取模**

循环中 `i < n`，`cost[i % n]` 的 `%n` 恒等于 `cost[i]`，完全多余。同理 `gas[(i+1)%n]` 当 `i=n-1` 时为 `gas[0]`，这里取模是有意义的（环回到 0），但单独看易误认为是多余的。

**4. 多余头文件**

```cpp
#include <stack>
#include <map>
#include <set>
#include <string>
```
均未使用。

**5. `fun` 调试函数遗留**

`fun` 是调试用的模拟函数，应删除。

**6. 数组使用不一致**

```cpp
int arr[9] = {3,1,1,3,4};  // 定义 9 个但只初始化 5 个
int brr[9] = {1,2,2,5,1};
for (int i = 0; i < 3; i++) // 只用了前 3 个
```
数组大小 9 但实际只用了 3 个元素，资源浪费。

**7. `vector<int> n(0)`**

应写作 `vector<int> gasVec;`，使用 `()` 构造不直观。且变量名 `n`, `m` 与数组长度 `n` 混淆——前者是数据容器，后者是题目的 `n` 参数。

## 改进建议

```cpp
int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
    int totalSurplus = 0, curTank = 0, start = 0;
    for (int i = 0; i < gas.size(); ++i) {
        int diff = gas[i] - cost[i];
        totalSurplus += diff;
        curTank += diff;
        if (curTank < 0) {
            start = i + 1;
            curTank = 0;
        }
    }
    return totalSurplus >= 0 ? start : -1;
}
```

## 点评

| 维度 | 评价 |
|------|------|
| 正确性 | ⚠️ 核心逻辑可工作，但实现有偏差 |
| 代码简洁性 | ⚠️ 逻辑绕、变量多 |
| 可读性 | ❌ 变量命名差、`t` 语义混乱 |
| 编码规范 | ❌ 多余头文件、数组浪费、遗留调试代码 |

核心贪心思路是对的，但代码组织混乱。建议采用标准的一次遍历贪心写法，逻辑清晰且不易出错。
