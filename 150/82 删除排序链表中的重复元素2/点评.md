# 82. 删除排序链表中的重复元素 II — 代码点评

## 使用的方法
**哑节点 + 双指针边扫边删（flag 标记）**：`r` 指向「保留链」链尾，`l1` 探测下一段的首节点，`l2` 在连续相等段内后移直至段末；发现 `l1` 的值有重复（`l1->val == l1->next->val`）就 `r->next = l2->next` 整段摘除并置 `flag=1` 让 `r` 不前进；否则 `r` 收下当前节点前进。摘除后不移动 `r`，以便下一轮继续判断新接上的节点。

## 复杂度分析
- 时间复杂度: O(n)（每个节点被扫描常数次）
- 空间复杂度: O(1)（仅一个哑节点与若干指针）

## 代码评价
- 优点:
  - **正确性经得起推敲**：对重复段整段摘除、且摘除后 `r` 原地等待下一轮判断，正确处理了「3,3,4,4,5 → 只剩 5」这类连续两段重复的样例；哑节点让链头也可被安全删掉
  - 复杂度达标 O(n) O(1)
- 可改进之处:
  - **`flag` 变量让流程偏绕**：`r` 是否前进要用 flag 事后判断，容易读丢逻辑；本质是「该轮有没有发生删除」。标准写法见题解解法一：摘除分支里 `pre`（r）不前进，唯一分支里 `pre = cur`，**无需 flag**——分支结构本身就表达了前进与否
  - 内层 `while (l2->next)` + 提前 break 来定位段末，等价于题解里更直白的 `while (cur->next && cur->next->val == v) cur = cur->next`
  - 有冗余防御（`if (!l1) break;`、`if (l1->next)` 后再判内层），可精简
- 代码风格: 思路对但分支+flag 组合可读性弱，建议改成「cur 值定段 + pre 接链」的无 flag 版本

## 总结
> 哑节点边扫边删，整段摘除逻辑正确、O(n) O(1)，AC；建议去掉 `flag`、让「是否前进」由分支本身表达，代码能明显更清晰。
