# 322. 零钱兑换 — 代码点评
## 使用的方法
动态规划（自底向上）。使用数组 `arr[i]` 表示凑出金额 i 所需的最少硬币数。对于每个金额 i，遍历所有硬币面额，用 `arr[i-coin] + 1` 更新最小值，无法凑出则记为 -1。

## 复杂度分析
- 时间复杂度：O(n * k)，外层遍历 1 到 amount（n），内层遍历所有硬币（k）。
- 空间复杂度：O(n)，动态分配大小为 amount+1 的数组 `arr`。

## 代码评价

**优点**：
- DP 的"完全背包"思路正确，核心转移逻辑 `arr[i] = min(arr[i], arr[i - coin] + 1)` 无误。
- 用 -1 标记不可达金额，语义直观。
- 预先将硬币面额对应的金额设为 1（即 `arr[coins[i]] = 1`），是正确的初始化优化。

**可改进**：
- **严重 Bug —— 数组未初始化**：`int *arr = new int[amount+1]` 分配后仅设置了 `arr[0]=0` 和各个硬币位置的值为 1，其余位置的 `arr[i]` 是**未定义的垃圾值**。在循环中，代码依赖 `arr[i-coins[j]] != -1` 来判断该子问题是否有解。但未初始化的元素可能恰好为 -1、0 或其他任意值，导致：
  1. 某些本可凑出的金额被错误标记为 -1（垃圾值恰好是 -1 的情况）
  2. 某些不可凑出的金额因垃圾值而给出错误的硬币数
  3. `min` 比较时可能使用到未初始化的值
  
  修复方法：在分配数组后，用循环将所有元素初始化为 -1 或使用 `vector<int> arr(amount+1, -1)`。

- **内存泄漏**：使用 `new int[amount+1]` 但无 `delete[] arr`，应改用 `vector<int>`。

- **头文件冗余**：包含了 `<stack>`、`<map>`、`<set>`、`<string>` 等未使用的头文件。

- **flag 逻辑可简化**：用 `flag` 变量判断是否有可行的硬币选择，实际上可以直接判断 `min` 是否仍为 `INT_MAX`。

**风格**：
- 变量名 `n` 表示硬币种类数可以接受，但 `arr` 建议改为 `dp`。
- `min` 是标准库名称，用作变量名虽然在此处合法（因为没 `using std::min`），但容易引起混淆。

## 总结
> AC ?

DP 思路正确，但**数组未初始化是最严重的问题**——未初始化的内存含有随机值，可能导致错误的计算结果。务必将所有 `arr[i]` 初始化为 -1（不可达标记）或 `amount + 1`（哨兵值）。此外需修复内存泄漏。
