# 380. O(1) 时间插入、删除和获取随机元素 — 代码点评

## 使用的方法
**哈希表 + 动态数组 + 交换删除**：`m`（值→数组下标）负责 O(1) 查重与定位，`arr` 负责按下标随机访问；删除时用末尾元素填掉被删位置并同步修正其下标（`arr[i] = arr[cnt-1]; m[arr[cnt-1]] = i`），再逻辑移除末尾。`cnt` 作逻辑长度，`getRandom` 用 `rand() % cnt` 取随机位。

## 复杂度分析
- 时间复杂度: insert / remove / getRandom 均摊 O(1)（`arr` 只在满时 push_back，摊还 O(1)）
- 空间复杂度: O(n)（哈希表 + 数组）

## 代码评价
- 优点:
  - **抓住核心难点**：用「交换删除」规避数组中间删的 O(n) 前移，直接命中题目要求的 O(1)；末尾元素回填后哈希表下标同步更新，逻辑严密
  - 细节处理得当：`insert` 复用被删后留下的空槽（`arr.size()==cnt` 才 push，否则原地写），删除末尾元素（自赋值 + 再 erase）也安全
- 可改进之处:
  - **用 `cnt` 作逻辑长度而数组从不真正缩小**：`arr` 只增不减，删除只在语义上生效，峰值内存不会释放；标准写法是删除时直接 `arr[i] = arr.back(); arr.pop_back()`，数组物理长度同步收缩，更贴近题解且免去 `cnt` 与 `arr.size()` 的并行维护
  - 可去掉 `cnt` 成员，一切以 `arr.size()` 为准，减少一处易失步的状态（当前 insert/remove/getRandom 都依赖它与数组同步，重构后可消除这类隐患）
  - `rand() % cnt` 在 LeetCode 上可用，若要更均匀可换 `mt19937`，非必需
- 代码风格: 正确但状态变量偏多，`cnt` 版可读性略逊于直接 `pop_back`

## 总结
> 哈希表+交换删除，思路与复杂度都对（各操作 O(1)），AC；建议用 `arr.back()`+`pop_back()` 替代手动 `cnt`，让物理数组真实收缩、状态单一，代码更简洁不易失步。
> AC ✓
