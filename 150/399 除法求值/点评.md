# 399. 除法求值 — 代码点评

## 使用的方法
**变量编号 + 带权图 DFS**：先用 `unordered_map<string,int>` 把出现过的变量编号，建两张 V×V 表——`g[a][b]` 存 `a / b` 的比值，`g_flag[a][b]` 表示这条边是否存在（反向边同时填 `1/v`）。每个查询从起点 DFS，沿路径把边权乘到出参 `r` 上，`flag` 记录路径上的点、回溯时复位；找不到就返回 `-1.0`。

## 复杂度分析
- 时间复杂度: O(Q · V³)——每次查询本质是一次 O(V²) 的矩阵式搜索，但 `fun` 的 `g`、`g_flag` **按值传参**，每层递归都要拷贝两张 V×V 表，把每次调用抬到 O(V²)（V ≤ 40 时实际开销很小，但与 207 题的"超内存"同源）
- 空间复杂度: O(V²)（两张 V×V 表）+ O(V) 递归栈（另有每层 O(V²) 的临时副本）

## 代码评价
- 优点:
  - **核心思路正确**：`a/b = (a/x)·(x/y)·(y/b)`，沿任意一条路径把边权相乘即可得到比值，与路径选择无关
  - 反向边只存一次比值（`1/v`），不会因为方向问题算错
  - 查询的两个变量只要有任一没出现过就提前返回 `-1.0`，不连通时 `f` 保持 false 也返回 `-1.0`，语义完整
  - `flag` 在回溯时复位（`flag[i] = 0`），允许搜索沿不同分支展开，不会因为一次失败就误判无解
- 可改进之处:
  - **`fun` 的两张矩阵表要改成引用**：`const vector<vector<double>>& g` / `const vector<vector<int>>& g_flag`（或干脆合并成一张表、用 0 表示无边）。现在每层递归都深拷贝 O(V²) 数据，是这份代码最该修的一处
  - 两张表可以合成一张：题目保证比值都是正数，用 `0.0` 表示"无边"即可，省一半内存与一半维护成本
  - 数据结构可以用邻接表（`vector<vector<pair<int,double>>>`）：邻居遍历从 O(V) 降到 O(度数)，空间也从 O(V²) 降下来
  - 查询同一个变量（`[x, x]`）时，现在靠"绕一圈 `a→i→a`、`g[0][i] · g[i][0] = 1`"偶然得到正确结果；建议开头显式加 `if (a == b) return 1.0;`，语义更明确
  - 更进一步的解法是**带权并查集**（`weight[x] = x / parent[x]`）：一次合并、查询近似 O(1)，不用每次查询重搜（见题解解法二）
  - 出参风格 `double& r, bool& f` 可以简化成让 `fun` 直接返回 `double`（找不到返回 -1），少两个参数、少一份状态
  - `fun` 的参数名 `a / b` 与"起点/终点"的语义不直观，建议 `cur / dst`
  - `main` 里用 C 数组手工拼测试数据比较绕（可以改成初始化列表），而且缺了 `["x","x"]` 这种"变量不存在"的查询用例；`#include <math.h>` 未使用
- 代码风格: `g / g_flag / um / cnt` 命名偏短；`g_flag` 单独存在的现象说明"边是否存在"本该由权重自身表达

## 总结
> 路径边权相乘的思路正确、边界与不连通情况都覆盖到了，AC；最该改的是 `fun` 的两个矩阵**按值传参**（每层递归都在拷贝 O(V²) 数据），改引用 + 合并成单表即可，进阶可用带权并查集把查询降到近似 O(1)。
