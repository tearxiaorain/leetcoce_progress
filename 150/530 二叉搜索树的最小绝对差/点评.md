# 530. 二叉搜索树的最小绝对差 — 代码点评
## 使用的方法
中序遍历收集数组。函数 `preorder`（实为**中序**遍历：左 → 根 → 右）把整棵树中序序列收集进 `vector<int> arr`，再扫描相邻元素差求最小值。

## 复杂度分析
- 时间复杂度：O(n)。中序遍历 O(n) + 相邻元素一次扫描 O(n)。
- 空间复杂度：O(n)。`arr` 保存全部 n 个节点值。

## 代码评价

**优点**：
- 核心思路正确：BST 中序递增，任意两节点的最小绝对差必出现在相邻元素之间，故相邻扫描即可。
- 代码简洁。

**可改进**：
- 函数名 `preorder` 与实际中序逻辑不符，应改名 `inorder`。
- 第 52 行 `// diff = fabs(diff);` 被注释掉，当前正确性依赖"中序递增 → diff 恒非负"这一隐含前提。一旦树不满足严格 BST 或遍历顺序被改动，将得出错误结果；建议显式 `abs`（或注明依赖前提），更稳妥。
- O(n) 的 `arr` 非必需：中序遍历时记录前驱节点实时更新最小差，空间可降到 O(h)（见题解解法二），Morris 遍历可到 O(1)（见题解解法三）。
- 头文件包含了一些未使用的 `<stack>`、`<queue>`、`<map>`、`<set>`、`<string>`、`<unordered_map>`、`<algorithm>`（实际用到 `<iostream>`、`<vector>`）。

**风格**：
- ACM 风格，`using namespace std;`。
- 辅助函数名与语义不符是主要可读性问题。

## 总结
> AC ✓

代码结果正确，利用"BST 中序递增 + 最小差在相邻"思路，复杂度 O(n)/O(n)。主要不足：函数命名误导、依赖递增隐含前提却注释掉 `fabs`、额外 O(n) 数组。最优为中序实时比较 O(n)/O(h)，空间更优可用 Morris O(n)/O(1)。
