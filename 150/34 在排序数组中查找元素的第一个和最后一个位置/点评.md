# 34. 在排序数组中查找元素的第一个和最后一个位置 — 代码点评

## 使用的方法
**三次递归二分**：先用 `find` 找到任意一个等于 `target` 的位置 `ind`（找不到就直接返回 `[-1,-1]`），再用 `findbegin`（`nums[mid] < t` 才右移）和 `findend`（`nums[mid] > t` 才左移）在 `[0, ind]`、`[ind, n-1]` 上分别收敛出左、右边界，最后用 `if (nums[en] != target) en--;` 把"第一个大于 target 的位置"修正回"最后一个等于 target 的位置"。

## 复杂度分析
- 时间复杂度: O(log n)（三次二分，常数 3）
- 空间复杂度: O(log n)（三个二分都写成尾递归，占递归栈；改循环即 O(1)）

## 代码评价
- 优点:
  - **结果正确**：`findbegin` 收敛到第一个 `>= target` 的位置，`findend` 收敛到最后一个 `<= target` 的位置，配合 `nums[en] != target → en--` 的修正，`[be, en]` 正是题目要求的区间
  - 边界考虑到位：空数组、target 比所有元素小/大、单元素、全相同元素（`[1,1,1]`）都有对应分支，`n == 0` 与 `ind == -1` 都提前返回
  - 两次边界搜索都是标准二分，满足题目的 O(log n) 要求
- 可改进之处:
  - **第一步 `find` 是多余的**：`lower_bound` 找到第一个 `>= target` 的位置后，判断该位置是否等于 target 就够了，3 次二分可以降到 2 次（见题解解法二）
  - `find` 中 `nums[mid] > t` 时递归传的是 `mid` 而不是 `mid - 1`，靠开头 `if (l == r) { if (nums[l] != t) return -1; }` 这个特判终止；能过但不是标准写法，一旦换成左闭右开区间就容易死循环
  - 三个函数都是尾递归，改成 `while (l < r)` 循环可把空间从 O(log n) 降到 O(1)，也省掉调用开销
  - `int mid = (l + r) / 2` 在极大区间有整型溢出风险，习惯写成 `l + (r - l) / 2`
  - 函数名 `find` 与 `std::find` 重名（又 `using namespace std`），建议改成 `findAny` / `lowerBound` / `upperBound`
  - `if (ind == -1) return res; else { ... }` 的 `else` 可去掉，减少一层缩进
- 代码风格: `find / findbegin / findend` 缺统一风格（`findBegin / findEnd`），`nums[mid] > t` 分支可补一句"答案在左半区"的注释

## 总结
> 三次二分得到正确的左右边界、O(log n) AC；可以简化为"lower_bound 判存在 + upper_bound 求右端"两次二分，并把手写二分统一成标准模板（不必依赖 `l == r` 特判终止）。
> AC ✓
