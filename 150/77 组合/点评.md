# 77. 组合 — 代码点评

## 使用的方法
DFS + 剪枝：实际生效的是 `fun_c`——`c` 为已取到的最大下标，`for(i=c+1; i<n; ++i)` 保证下标严格递增（数字去重、不产生排列顺序），并带剪枝 `n-c < k-cnt`。外层 `combine` 手动先放首个元素再调 `fun_c`；另留有一个用 `flag` 的 `fun_a`（排列式写法，已注释未用）。

## 复杂度分析
- 时间复杂度: O(C(n, k) × k)，C(n,k) 个组合，每个收集 O(k)
- 空间复杂度: O(k)，递归深度 + path

## 代码评价
- 优点:
  - 结果正确：对 `n=4,k=2` 输出 6 个组合且均为严格升序、无重复，验证通过
  - 剪枝判断已经出现（"剩余不够就停"的方向对了），在数据偏大时能显著提速
- 可改进之处:
  - **首元素由外层循环"手动铺垫"很绕**：`combine` 里 push 第一个数再进 `fun_c`，把本应统一的"从 start 起填 cnt 个"拆成了两步。合并成单个 `dfs(start, cnt)`（`path.size()` 即已选数）即可让代码自解释
  - 残留的 `fun_a`、`flag`、注释掉的调用都属于死代码，删掉降低困惑
  - 剪枝 `n-c < k-cnt` 是"从 c+1 起还够不够"的判定，用下标数应为 `(n-1)-(c+1)+1 = n-c-1`，这里写成 `n-c` 偏宽松一格（不剪错但少剪一刀），建议写标准形式 `i <= n - (k - path.size()) + 1` 作为循环上界
  - 函数名 `fun_a/fun_c` 无信息量；`path.push_back(i+1)` 里 +1 的换算在 `n` 与下标间来回跳，易错
- 代码风格: 正确但结构冗余；收敛成"单函数 + 直接循环上界剪枝"后是标准最优形态

## 总结
> 组合去重与剪枝思路已到位，主要问题在**外层手动放首元素的冗余组织与死代码**；重构成 `dfs(start)` 单函数 + 上界剪枝即为教科书实现。
