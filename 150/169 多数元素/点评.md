# 169. 多数元素 — 代码点评

## 使用的方法
排序 + 线性扫描——先排序数组，再遍历统计连续相同元素个数，当个数 >= n/2 时返回该元素。

## 复杂度分析
- 时间复杂度: O(n log n)，排序主导
- 空间复杂度: O(1)（忽略排序的栈空间），只使用了常数额外空间

## 代码评价
- 优点: 利用排序将相同元素聚集在一起，思路正确，能得出正确答案。
- 可改进之处:
  1. **排序后无需遍历**: 排序后多数元素一定出现在中间位置 `nums[n/2]`，直接返回即可，不需要再扫描统计。当前代码的遍历是冗余的。
  2. `count` 的逻辑不够清晰：从 0 开始计数，对于连续相同元素每遇到一个就把 count+1，但实际上对于长度 L 的连续相同元素，count 最大只会是 L-1（因为从第二个开始计数）。条件 `count >= n/2` 在这种情况下仍然正确，但整个扫描过程多余。
  3. **边界情况不健壮**: 对于长度 n=1 的数组，循环体 `for(i=0;i<n;i++)` 的 `if(i)` 判断使循环体从未执行，`ind` 保持为 0，返回 `nums[0]` 碰巧正确。但这样做依赖初始巧合而非显式逻辑。
  4. 没有使用 Boyer-Moore 投票算法，时间复杂度可优化到 O(n) 且 O(1) 空间。
  5. 缺少函数封装和 main 外部的测试结构。
- 代码风格: 基本清晰，但 `if(i)` 的判断风格略晦涩，建议用 `if(i > 0)`。

## 总结
> 排序 + 扫描的思路正确但繁琐——排序后取中位数即可一行解决。真正的 O(n) 最优解是 Boyer-Moore 投票算法。
