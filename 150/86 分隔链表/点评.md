# 86. 分隔链表 — 代码点评

## 使用的方法
**单个哑节点 + 双工作指针原地重排**：哑节点 `l1` 充当"小于 x 区域"的哨兵并指向原链头，`l2` 是扫描指针。先把链头一段连续 `< x` 的节点原样保留并让 `l1` 停在该区末尾；随后 `l2` 向后扫描：遇到 `>= x` 就继续走，遇到 `< x` 的节点就把它从原链中拆出，**插到 `l1`（<x 区尾）之后**并把 `l1` 前移，扫描指针从被拆节点的后继继续。全程只改指针，返回哑节点 `next`。

## 复杂度分析
- 时间复杂度: O(n)（`l2` 单次扫描，每个节点至多被拆一次）
- 空间复杂度: O(1)（仅 1 个新建哑节点）

## 代码评价
- 优点:
  - **正确性扎实**：官方样例 + 5000 组随机对拍（与"收集 <x 再收集 >=x"的稳定参考完全一致）全过；两种情况内部相对顺序都保持，稳定且满足题意
  - 原地改指针、无新建业务节点，O(n) O(1) 达标；`all < x`、`all >= x`、单节点、空链表等边界都能直接走通（有随机覆盖）
- 可改进之处:
  - **`l1/l2` 职责靠命名猜不透**：`l1` 指 <x 区尾、`l2` 是扫描指针，且中途又 `l2 = l1` 复用变量，读起来费解。标准做法是**两个哑节点 `small` / `large`** 各接一条链，单遍按值拆链后拼接，逻辑和命名都直白得多
  - 拆-插的指针重接（先 `t = l2->next->next` 保住后继，再改两条 `next`）正确但容易写错，双哑节点写法天然免去这些交错
  - 哑节点 `new` 出来从未 `delete`；可改用栈上节点（函数返回时不依赖它存活，因返回的是其 `next`）
  - `if (!head) return nullptr;` 与 `if (!head->next) return head;` 属冗余特判，主流程已能自然处理
- 代码风格: 正确、紧凑，但可读性不如双哑节点版本

## 总结
> 原地单哑节点分隔正确（固定样例 + 5000 组随机对拍全过），复杂度达标；建议改写为"双哑节点 small/large 拆链拼接"，命名与结构都更清晰、也更难写错。
