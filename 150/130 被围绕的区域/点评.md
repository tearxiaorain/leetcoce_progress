# 130. 被围绕的区域 — 代码点评

## 使用的方法
**一个带模式开关的递归 DFS**：`find(board, flag, x, y, m, n, op)` 用 `op` 区分两种任务——`op == 0` 时探测（越界即返回 true，表示这块' O '连通到边界；`flag[x][y] = 1` 标记已走），`op == 1` 时翻转（把 `flag == 1` 的格子改成 `'X'` 并置 `flag = 2`）。外层对每个未访问的 `'O'` 先探测，探到"没触边"再翻转整块。

## 复杂度分析
- 时间复杂度: O(m·n)（每个被围的块走两遍：探测 + 翻转；未触边的块各格只被访问常数次）
- 空间复杂度: O(m·n)（flag 矩阵）+ O(m·n) 递归栈（最坏整张棋盘是一片 'O'）

## 代码评价
- 优点:
  - **判定逻辑正确**：越界即"连通到边界"、`flag` 保证每个格子只探测一次，探测结果通过返回值一路上传，等价于"这块是否与边界连通"
  - **四个方向用四个独立变量接收**（而不是直接写 `return f(上) || f(下) || …`），避免了短路求值导致部分分支不执行、连通块搜不全的问题，这一点想到了很关键
  - 两阶段语义（先探测、后翻转）与"边界洪水填充"等价，思路是对的
  - `flag` 用 0/1/2 区分"未访问 / 已探测 / 已翻转"，翻转阶段只认 `flag == 1`，不会重复翻转
- 可改进之处:
  - **递归深度风险最大**：board 最大 200 × 200 = 4 万格，整片连通的 'O' 会让递归深度达到 4 万层，很容易爆栈；建议把 DFS 换成显式栈/队列（BFS），或直接改用"从四条边上的 'O' 淹没标记，最后统一翻转"的写法
  - **一个函数承担两种语义**：`op` 开关让每次读代码都要在"探测"和"翻转"两套分支间切换，拆分更清晰（如 `bool touchesBorder(...)` + `void flipRegion(...)`）
  - 被围的块要遍历两遍（探测一遍、翻转一遍），用"边界淹没"只需对整表扫两遍、常数更小，也不用收集块内格子
  - 函数名 `find` 与 `std::find` 重名（又 `using namespace std`），建议 `probe` / `dfs`
  - `solve` 直接访问 `board[0].size()`，空输入会崩，建议先 `if (board.empty() || board[0].empty()) return;`
  - `m`、`n` 每次递归都作为参数传递，可以提升为类内成员/全局常量，函数签名更短
  - `main` 的样例只把 4×4 数组的前 2×2 填进 board（四个格子全在边界上），**没有测到"中间被围的 O 变 X"这条主路径**，建议直接用官方 4×4 用例
- 代码风格: `flag` 的 0/1/2 三种含义没有注释说明，`op` 这个参数名也看不出是"阶段"的意思

## 总结
> 先探测连通块是否触边、再回填翻转，思路与实现都正确，AC；建议把"探测/翻转"拆成两个函数或直接换成"从边界淹没 + 统一翻转"的写法，并把递归改成显式栈以规避 4 万层的爆栈风险。
> AC ✓
