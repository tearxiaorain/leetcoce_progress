# 209. 长度最小的子数组 — 代码点评

## 使用的方法
文件里共有三个版本，**主用（被 main 调用的）是 `minSubArrayLen`：前缀和 + 二分查找**——对每个起点 `i`，用二分找第一个使 `sum[mid]-sum[i]+nums[i] ≥ target` 的 `mid`，更新最短长度，O(n log n)。
另有 `minSubArrayLen2`（O(n²) 暴力双循环）和 `minSubArrayLen1`（一个"从两端收缩"的实验性贪心，**未被主路径使用**）。

## 复杂度分析
- 主用版本: O(n log n) 时间，O(n) 空间（前缀和）
- 暴力版本: O(n²) 时间，O(n) 空间

## 代码评价
- 优点:
  - 主用的前缀和 + 二分写法正确，处理了 `n==0` 与"总和不达标返回 0"两个边界；已在 6 组样例 + 3000 组随机对拍下与暴力全一致
  - 二分找"第一个达标位置"用 `r=mid` / `l=mid+1` 的模板正确，避免了越界
- 可改进之处:
  - **不是最优解**：本题标准答案是双指针滑动窗口 O(n) O(1)，比前缀和 + 二分省一个 log 且省空间，建议主用
  - `minSubArrayLen1` 是危险的残留：它按"删掉哪端仍达标、两端数值谁大删谁"来收缩，**并不能保证收缩到最短窗口**，属于实验性写法却没有任何标记，建议直接删除，避免日后误用
  - 保留 O(n²) 暴力版可以，但主函数里堆了三个版本，冗余；留"暴力（可注释掉）+ 最优"即可
  - 前缀和存成 `sum` 并从 `sum[i]+nums[i]` 还原区间和，略绕；可直接用 `pre[j+1]-pre[i]` 的标准前缀差
- 代码风格: 分段清晰，但"同一题三种解法并存 + 一个未加说明的实验版"容易误导后续维护

## 总结
> 主用二分版本正确（样例 + 随机对拍全过），边界齐全；建议删掉未使用、正确性可疑的 `minSubArrayLen1`，并把标准答案收敛为 O(n) 双指针滑动窗口。
