# 97. 交错字符串 — 代码点评

## 使用的方法
**二维 DP（bool 表）**：`dp[i][j]` 表示 `s1` 前 `i` 个 + `s2` 前 `j` 个能否拼出 `s3` 前 `i+j` 个。第 0 行按"只用 s2"逐字符初始化、第 0 列按"只用 s1"初始化，内层用 `b1 = dp[i-1][j] && s1[i-1] == s3[i+j-1]`、`b2 = dp[i][j-1] && s2[j-1] == s3[i+j-1]`，最后 `dp[i][j] = b1 || b2`。

## 复杂度分析
- 时间复杂度: O(m·n)
- 空间复杂度: O(m·n)

## 代码评价
- 优点:
  - **转移与初始化都是标准解**：`dp[0][0] = true`、第一行/列的前缀相等判定正确，内层"`s3` 最后一位由 `s1` 或 `s2` 提供"两种来源用 `||` 合并，语义清晰
  - 边算边取 `b1 / b2` 的写法比直接写一长串逻辑表达式更好读、也便于调试
  - 官方样例（`aabcc + dbbca → aadbbcbcac / aadbbbaccc`）与空串、单字符等边界都能得到正确结果
- 可改进之处:
  - **长度守卫条件写错了**：现在是 `if (m + n < k) return false;`，只挡住了"`s3` 比两串之和更长"的情况。当 `s3` 更**短**时（例如 `s1 = "ab", s2 = "cd", s3 = "a"`）不会提前返回，随后 `s3[i + j - 1]` 会**越过字符串末尾取字符**，属于未定义行为（未定义行为下恰好返回 false，是运气好）。应改成 `if (m + n != k) return false;`
  - **函数里留着调试用的 dp 矩阵打印**，每次调用都把整张表输出到 stdout，LeetCode 上虽不影响判题但毫无必要，建议删除
  - `vector<vector<bool>>` 虽然是本题的常用写法，但空间可进一步压到 O(n)：转移只依赖上一行同列和本行左邻，用一维滚动数组即可（见题解解法三）
  - `bool b1, b2; b1 = b2 = false;` 紧接着又整体赋值，前面那次初始化是多余的
  - 变量命名把两个维度混在一起：第 0 行对应"只用 `s2`"，但初始化循环变量却叫 `i`（`for (int i = 1; i < n + 1; i++) dp[0][i] = ... s2[i-1]`），容易看错，建议改用 `j`
- 代码风格: 用 `k` 表示 `s3` 长度、同时又出现 `i + j - 1` 的下标，建议直接用 `s3[i + j - 1]` 或在转移里保留一个 `idx` 变量点明含义

## 总结
> 二维 DP 的初始化与转移都正确、O(mn) AC；必须修的是长度判定 `<` 应为 `!=`（否则 `s3` 偏短时会越界读），顺手删掉调试打印并把空间滚成一维。
> AC ✓
