# 70. 爬楼梯 — 代码点评
## 使用的方法
动态规划（自底向上）。使用一维数组 `arr` 存储 dp 值，`arr[i] = arr[i-1] + arr[i-2]`，本质上就是斐波那契数列递推。

## 复杂度分析
- 时间复杂度：O(n)，一次 for 循环从 3 遍历到 n。
- 空间复杂度：O(n)，动态分配了大小为 n+1 的数组 `arr`。

## 代码评价

**优点**：
- DP 递推逻辑正确，核心转移方程 `arr[i] = arr[i-1] + arr[i-2]` 无误。
- 对 n=0、n=1、n=2 做了特判，避免数组越界。

**可改进**：
- **内存泄漏**：使用 `new int[n+1]` 分配数组，但缺少对应的 `delete[] arr`，导致内存泄漏。应使用 `vector<int> arr(n+1)` 替代原始指针。
- **n=0 的返回值不一致**：当 n=0 时返回 0，但按照组合数学和 LeetCode 官方定义，`climbStairs(0)` 应该返回 1（原地不动也是一种方法）。本题 LeetCode 约束 n>=1，但规范起见 dp[0] 应初始化为 1。
- **空间可优化到 O(1)**：dp[i] 仅依赖前两个状态，用两个滚动变量即可代替整个数组。
- **头文件冗余**：包含了 `<stack>`、`<map>`、`<set>`、`<string>` 等未使用的头文件，应只保留实际需要的 `<iostream>` 和 `<vector>`。

**风格**：
- 代码格式较紧凑，`if`/`else` 缺少数空格（如 `if(n==0)`），建议统一为 `if (n == 0)`。
- 变量命名 `arr` 过于泛化，建议用 `dp` 更能体现动态规划的含义。

## 总结
> AC ✓

DP 逻辑正确，转移方程无误。主要问题是使用裸指针导致内存泄漏，以及 n=0 的特殊处理与标准定义有偏差。建议改用 `vector` 并优化空间到 O(1)。
