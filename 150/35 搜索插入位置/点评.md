# 35. 搜索插入位置 — 代码点评

## 用户算法概述

用户采用二分查找 + 边界回退判断的方式：先用经典二分模板查找 target，若找到直接返回；若未找到，通过比较 `nums[mid]` 与 `nums[mid+1]` 确定插入位置。

## 用户复杂度分析

- 时间复杂度：O(log n) — 二分查找
- 空间复杂度：O(1)

## 代码中存在的问题

### 1. 循环退出后的返回值处理不够优雅

```cpp
if (nums[mid] == target) return mid;
if (nums[mid] < target && nums[mid + 1] >= target) return mid + 1;
return mid;
```

当 while 循环因 `left > right` 正常退出（target 不存在）时：

- `nums[mid+1]` 可能越界（当 mid 为最后一个元素时）
- 实际上二分结束后，`left` 恰好指向第一个 >= target 的位置，**直接 `return left` 即可**，无需额外判断

例如 `[1,3]` 中搜索 `2`：
- `mid=0`，`nums[0]=1 < 2`，`left=1`
- `mid=1`，`nums[1]=3 > 2`，`right=0`
- 循环结束 `left=1 > right=0`
- `nums[mid]=3 > target`，不满足 `nums[mid] < target && ...`
- 执行 `return mid` 即返回 1，恰好正确
- 但 `[1,5]` 搜索 `3`：`mid=0`，`1<3`，`left=1`；`mid=1`，`5>3`，`right=0`；循环结束，`mid=1, nums[1]=5`，`nums[mid] > target`，走 `return mid` 返回 1，正确
- 然而 `[1,3,5]` 搜索 `4`：`mid=1, 3<4, left=2`；`mid=2, 5>4, right=1`；循环结束 `mid=2`，`nums[2]=5 > target`，`return mid` 返回 2，正确

虽然在大多数情况下恰好正确，但依赖巧合而非确定性逻辑，是代码的隐患。

### 2. 不必要的提前边界判断

```cpp
if (nums[left] > target) return 0;
if (nums[right] < target) return right + 1;
```

这两行作为优化是可接受的，但它们并非必要——标准二分查找结束后 `left` 自然指向正确位置。若追求代码简洁，可以去掉。

### 3. 无效的 mid 初始化

```cpp
int mid = right / 2;
```

这个初始值会被循环内部的 `mid = (left + right) / 2` 立即覆盖，属于无效代码。

### 4. 测试用例不够充分

`main()` 中只测试了 `[1,3]` 搜索 `2`，未覆盖目标在末尾插入、目标在开头插入、目标已存在等场景。数组声明 `arr[9]` 有 9 个元素但初始化只给了 6 个值。

## 建议改进

```cpp
int searchInsert(vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target)
            left = mid + 1;
        else if (nums[mid] > target)
            right = mid - 1;
        else
            return mid;
    }
    return left; // 简洁且正确
}
```

## 评分

| 维度 | 评价 |
|------|------|
| 思路 | 二分查找方向正确 |
| 代码正确性 | 大部分情况下正确，但边界处理依赖巧合 |
| 复杂度 | O(log n) O(1)，达标 |
| 代码风格 | 有冗余代码和无效初始化 |
